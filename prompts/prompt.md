# 과정별 실습 프롬프트

같은 프로젝트 폴더에서 회차와 번호 순서대로 프롬프트를 하나씩 입력합니다.

### 1회차: 서버와 로그인

1. 웹사이트는 내가 보내는 프롬프트에 따라 만들어줘. 다른 저장소의 제작 가이드나 완성 코드는 읽지 말아줘.
   이 폴더에서 웹 서비스를 만들 수 있게 Node.js와 Git이 있는지 확인해줘. 없으면 설치 방법을 알려줘. 로그인이나 설치 승인처럼 내가 해야 할 일은 알려줘.

2. 텀블러 공장의 품질을 관리하는 웹 서비스를 만들어줘. Node.js 서버와 HTML, CSS, JavaScript를 사용하고 내 컴퓨터에서 실행해줘. 홈, 검사 목록, 검사 등록, 설정 화면을 만들고 이동할 수 있게 해줘.

3. 로그인과 로그아웃을 추가해줘. 로그인하지 않은 사람은 검사 화면에 들어갈 수 없게 해줘. 서버는 내 컴퓨터에서만 접속되게 하고 연습용 비밀번호는 내가 정하게 해줘. 비밀번호는 화면이나 저장소에 공개하지 마.

### 2회차: 검사 등록과 품질 현황

1. https://github.com/startup-life/manufacturing-quality-dashboard-student 의 standards에서 Rev.A.json, Rev.B.json, notebooklm-Rev.A.md, notebooklm-Rev.B.md만 같은 경로로 가져와줘. 검사기준 원문은 바꾸지 말아줘.

2. 수업용 사진은 https://github.com/startup-life/manufacturing-quality-student-images 저장소의 ZIP을 받아 프로젝트의 assets/quality-photos에 풀어줘.

3. 검사 등록 화면에서 텀블러 제품, 검사기준, 검사 시각, 중량, 메모와 사진을 고르고 기록을 저장하게 해줘. 중량을 입력하지 않으면 미측정으로 표시해줘. 고른 제품과 기준의 중량 범위도 보여줘. 내 사진을 직접 올릴 수도 있게 해줘. 검사 기록과 사진은 내 컴퓨터에 저장하고 서버를 다시 켜도 남게 해줘.

4. 홈에 오늘 검사 건수와 검사 카드를 보여주고, 검사 목록과 상세 화면을 추가해줘. 상세에서 사진과 입력 내용을 확인하고 수정할 수 있게 해줘.

### 3회차: Google 시트와 Drive 저장

1. 검사 기록을 내 컴퓨터 또는 Google 중에서 골라 저장하게 해줘. 현재 어느 저장소를 쓰는지 화면에 표시하고 기존 기록이 사라지지 않게 해줘.

2. Google Apps Script를 사용해 검사 기록은 내 Google 시트에, 사진은 내 Google Drive에 저장하고 다시 불러오게 해줘. 실제 저장과 재조회가 성공했을 때만 연결됐다고 표시하고 로컬 저장도 유지해줘.

3. Google 로그인, Apps Script 프로젝트 생성과 배포를 도와줘. 로그인과 권한 승인은 내가 직접 할게. 이미 만든 프로젝트가 있으면 중복 생성하지 말고, 웹앱 접근 범위를 설명한 뒤 내가 확인하면 진행해줘.

### 4회차: Gemini 사진 판독

1. https://github.com/startup-life/manufacturing-quality-dashboard-student 에서 prompts/gemini-v1.md만 같은 경로로 가져와줘. 사진 판독 때 이 문구와 standards의 검사기준을 사용해줘.

2. 검사 상세에 AI 사진 판독 버튼을 만들어줘. 우선 연습용 결과로 작동시키고 실제 판독과 구분해 표시해줘. 사진에서 확인할 수 없는 내용은 추측하지 말고, 최종 판단은 사람이 한다고 알려줘.

3. OnePort 주소 https://oneport.kr/v1 과 모델 gemini-3.8-flash로 Gemini 사진 판독을 연결해줘. API 키는 내가 직접 비공개 설정에 넣게 하고 화면과 Git에 노출하지 마. 실제 연결이 실패하면 이유를 표시해줘.

4. 판독 결과와 시각을 검사 기록에 저장하고 다시 열어 볼 수 있게 해줘. 사진이나 검사 정보가 바뀌면 이전 판독을 다시 확인하라고 알려줘.

### 5회차: NotebookLM으로 검사기준 확인

1. standards 폴더의 notebooklm-Rev.A.md와 notebooklm-Rev.B.md를 NotebookLM에 올려 검사기준 노트북을 만드는 방법을 알려줘. 로그인과 권한 승인은 내가 직접 할게.

2. 검사 상세에 '검사기준 확인' 버튼을 추가해줘. 사진 판독 내용과 검사 정보를 기준으로 NotebookLM에 질문하고, 답변과 근거 출처를 보여줘. 필요하면 제3자 nlm CLI를 사용하고 설치·로그인 방법을 알려줘. 실제 연결 전에는 연습용 답변을 구분해 표시해줘.

3. 확인한 출처와 내 대조 메모를 검사 기록에 저장해줘. 실제 연결이 실패하면 오류를 알리고, 실제 답변인 것처럼 연습용 결과를 보여주지 마.

### 6회차: 사람의 판단과 이력

1. 검사 상세에 사람이 최종 판단을 남기는 화면을 만들어줘. 판정은 정상(OK), 불량(NG), 보류(HOLD) 중에서 고르고, 불량 내용과 조치 메모, 판단 이유를 기록하게 해줘. 중량이 미측정이면 정상으로 저장하지 못하게 해줘. AI 결과는 참고이며 출하 승인으로 자동 처리하지 마.

2. 판단을 바꿀 때 변경 이유와 시각을 이력으로 남기고, 홈과 목록에는 가장 최근 판단을 표시해줘. 내 컴퓨터와 Google 저장 방식 모두에서 이력이 남게 해줘.

3. 사진 등록부터 AI 판독, 기준 확인, 사람의 판단과 조치 기록까지 순서대로 점검해줘. 연결되지 않은 서비스가 있어도 사람은 직접 판단할 수 있게 해줘.

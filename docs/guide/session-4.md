# 4회차 보충 문서: Gemini 사진 판독

이 문서는 AI 도구가 코드를 만들 때 읽는 자료입니다. 수강생은 이해하지 않아도 됩니다.

- 프롬프트가 요청한 일만 합니다. 이 문서의 내용을 한 번에 모두 만들지 않습니다.
- 앞 회차 문서와 다르면 번호가 큰 문서를 따릅니다. 이 회차가 바꾸는 앞 회차 약속: 보고서 검토 대기 숫자와 거르기(2회차 문서 "서버 기능 목록"의 `GET /api/home`의 "지금은 늘 0"과 `review=pending`의 "지금은 하나도 나오지 않습니다")는 이 문서 "다시 판독 필요와 검토 대기"의 "검토 대기" 기준으로 바꿉니다. Google 쪽 일 목록(3회차 문서의 "Google 쪽 일 여섯 가지")에 이 문서 "Google 쪽에 더할 일"의 네 가지를 더합니다. 시트의 탭 목록(3회차 문서의 "Google 쪽 일 여섯 가지"와 "서버가 Google을 쓰는 법")에 이 문서 "판독 결과와 저장"의 탭을 더합니다. `gas:init`(3회차 문서의 "수강생이 치는 명령")은 하던 일을 마친 뒤 이 문서 "OnePort 키"의 키 넣기까지 합니다. `gas:push`(3회차 문서의 "수강생이 치는 명령")와 `gas/Code.js` 한 파일(3회차 문서의 "Google 쪽 코드의 틀")에는 이 문서 "Google 쪽에 더할 일"의 함께 쓰는 코드가 더해집니다. 저장 방식 답(3회차 문서 "저장 방식 고르기"의 `GET /api/operations`)에는 이 문서 "판독 방식 고르기"의 두 항목을 더합니다.
- 맨 끝의 끝 표시를 만들어 `AGENTS.md`가 말한 대로 답의 마지막 줄에 적습니다.

## 이번 회차가 끝나면 되는 것

사진을 등록하면 AI 판독이 저절로 시작되고, 검사 상세 2번 탭에 결과 6항목과 배지가 보입니다. 다시 판독하고, 판독 결과 두 개를 나란히 비교합니다. 1번 탭에서 제품이나 중량을 바꾸면 이전 결과에 "다시 판독 필요"가 붙고, 홈 "보고서 검토 대기"가 판독한 검사를 셉니다. 설정에서 Gemini 지시문 v1~v3을 고르고, 고친 글을 새 버전으로 저장합니다. `.env`의 `GEMINI_MODE`로 판독 끄기(`off`), 연습용(`mock`), 실제 Gemini(`live`)를 고릅니다.

## 판독 방식 고르기

판독 방식은 `.env`의 `GEMINI_MODE`로 고릅니다.

| 값 | 뜻 | 화면에 쓰는 이름 |
|---|---|---|
| `off` | 판독하지 않음(사람이 직접 판단) | 꺼짐(off) |
| `mock` | 연습용 판독 | 연습용(mock) |
| `live` | 실제 Gemini 판독 | 실제 Gemini(live) |

| 경우 | 약속 |
|---|---|
| `GEMINI_MODE`가 없음, `STORAGE_MODE=mock` | `off`로 봅니다 |
| `GEMINI_MODE`가 없음, `STORAGE_MODE=live` | `live`로 봅니다 |
| `off`·`mock`·`live`가 아닌 값 | 서버를 켜지 말고 고칠 방법을 한 줄로 알려 줍니다 |
| `STORAGE_MODE=mock`에 `live`를 적음 | 서버를 켜지 말고 고칠 방법을 한 줄로 알려 줍니다 |
| `STORAGE_MODE=live`에 `mock`을 적음 | 서버를 켜지 말고 고칠 방법을 한 줄로 알려 줍니다 |

`GET /api/operations`의 답에 `"gemini_mode": 값`과 `"gemini_label": 화면에 쓰는 이름` 두 항목을 더합니다. 앞의 항목은 그대로 둡니다.

설정 화면에는 저장소 줄과 같은 꼴로 지금 판독 방식을 "Gemini 판독: (화면에 쓰는 이름)" 한 줄로 보여 줍니다. 예: "Gemini 판독: 연습용(mock)".

## 원문 파일과 수정본

| 폴더 | 파일 | 뜻 |
|---|---|---|
| `standards` | `notebooklm-Rev.A.md`, `notebooklm-Rev.B.md` | 검사기준 원문 |
| `prompts` | `gemini-v1.md`, `gemini-v2.md`, `gemini-v3.md` | Gemini 지시문 원문 |
| `prompts` | `notebooklm-v1.md`, `notebooklm-v2.md`, `notebooklm-v3.md` | NotebookLM 질문 원문 |

| 항목 | 약속 |
|---|---|
| 기본 원문 | `prompts`의 여섯 파일은 "기본 원문"이며 앱이 고치지 않습니다. 화면에서 버전 이름은 `v1`, `v2`, `v3`입니다 |
| 처음 쓰는 지시문 | 지시문을 따로 고르지 않으면 `gemini-v3.md`를 씁니다 |
| 수정본 | 설정에서 고친 글은 기본 원문을 덮어쓰지 않고 "v3 · 수정본 10-30 14:05"처럼 새 버전으로 쌓습니다. 이름 맨 앞은 고쳐 쓴 지시문의 v1~v3입니다 |
| 수정본 저장 위치 | 저장 방식과 상관없이 내 컴퓨터 `runtime` 폴더에 둡니다. 파일은 `runtime/custom-prompts.json`이고 안은 `[{"name": 이름, "text": 글}, ...]` 모양입니다 |

| 주소 | 하는 일과 요청 | 답 |
|---|---|---|
| `GET /api/prompts` | 지시문 목록(기본 원문 v1~v3 다음에 수정본) | `{"default": "v3", "prompts": [{"name": 이름, "text": 글, "custom": 수정본이면 true}, ...]}` |
| `POST /api/prompts` | 수정본 저장. 요청은 `{"base": 고쳐 쓴 버전 이름, "text": 글}` | 저장한 것 하나 `{"name": 이름, "text": 글, "custom": true}` |

설정 화면에 "Gemini 판독 지시" 칸을 둡니다.

| 칸 | 약속 |
|---|---|
| 버전 목록 | `GET /api/prompts`의 목록(기본 원문 v1~v3 다음에 수정본)입니다. 처음에는 `default`(v3)를 골라 둡니다 |
| 글 상자 | 고른 버전의 글을 보여 주고, 사용자가 고칠 수 있습니다 |
| "수정본 저장" 버튼 | 글 상자의 글을 `POST /api/prompts`로 새 버전으로 저장합니다. `base`는 지금 고른 버전의 v1~v3입니다(수정본을 골랐으면 그 이름 맨 앞의 v1~v3). 기본 원문은 덮어쓰지 않습니다. 저장하면 목록을 다시 받아 새 수정본을 골라 둡니다 |

## 판독 결과와 저장

판독 결과는 6항목이고 JSON 키는 한글 항목 이름 "판정", "불량유형", "관찰·수치 근거", "적용 기준과 출처", "권고 조치", "사람 승인 필요 여부"를 그대로 씁니다. 값은 모두 문자열이고 "판정"은 `OK`, `NG`, `HOLD` 중 하나입니다.

판독 결과마다 판독할 때의 제품·중량·사진 목록, 검사기준 버전, 지시문 버전 이름과 글, 판독 방식(`mock`·`live`), 만든 시각을 함께 저장합니다. 판독 결과 한 건의 모양입니다.

```json
{"result_id": "GR-3fa9c1d2", "inspection_id": "INSP-20261029-3fa9c1d2", "created_at": "2026-10-29 14:05:09", "mode": "mock", "revision": "Rev.A", "instruction_name": "v3", "instruction_text": "지시문 글", "product_id": "P-BLACK", "weight_g": 550, "images": ["/uploads/(파일 이름)"], "result": {"판정": "HOLD", "불량유형": "글", "관찰·수치 근거": "글", "적용 기준과 출처": "글", "권고 조치": "글", "사람 승인 필요 여부": "글"}}
```

| 항목 | 약속 |
|---|---|
| `result_id` | 판독 결과 번호입니다. 서버가 만듭니다. 모양은 `GR-xxxxxxxx`입니다(x는 0~9·a~f 8글자) |
| `created_at` | 만든 시각입니다. 한국 시각 "YYYY-MM-DD HH:MM:SS" 글입니다 |
| `mode` | 판독 방식입니다. `mock` 또는 `live`입니다 |
| `revision` | 판독에 쓴 검사기준 버전입니다 |
| `instruction_name`, `instruction_text` | 지시문 버전 이름과 그 글입니다 |
| `product_id`, `weight_g`, `images` | 판독할 때의 제품, 중량, 사진 목록입니다. 2회차 문서의 "검사 한 건"과 같은 모양입니다 |
| `result` | 6항목입니다 |

판독 결과는 검사와 같은 곳에 저장합니다.

| 저장 방식 | 저장 위치 |
|---|---|
| 내 컴퓨터 저장(`STORAGE_MODE=mock`) | `runtime` 폴더. 파일은 `runtime/gemini-results.json`이고 안은 판독 결과 한 건의 목록입니다 |
| Google 저장(`STORAGE_MODE=live`) | Google 시트의 `gemini_results` 탭. 판독 결과 한 건에 한 줄입니다 |

2번 탭, 홈 "보고서 검토 대기", 카드 목록은 지금 저장 방식의 판독 결과를 읽습니다(Google 저장이면 시트의 `gemini_results` 탭).

`gemini_results` 탭의 머리글은 `result_id`, `inspection_id`, `created_at`, `mode`, `revision`, `instruction_name`, `instruction_text`, `product_id`, `weight_g`, `images`, `result`입니다. `images`와 `result` 칸에는 값을 JSON 글로 적고, 읽을 때 위 모양으로 되돌립니다.

이 탭과 머리글은 Google 쪽 시트 만들기(`setup`) 목록에 더해, `npm.cmd run gas:init`을 다시 실행하면 빠진 탭·칸이 생기게 합니다(이미 있으면 그대로). Google 쪽 저장 담당 코드가 쓸 수 있는 탭·칸이 정해져 있으면 이 탭과 칸도 쓸 수 있게 넓힙니다.

## Google 쪽에 더할 일

Google 쪽 코드에 더하는 일은 아래 네 가지입니다. 3회차 코드의 일 이름·탭 이름에 기대지 말고, Google 쪽 코드에 이미 있는 요청·답 방식(3회차 문서의 "Google 쪽 코드의 틀")을 그대로 따라 일을 더합니다. "답"은 `{"ok": true, "data": 결과}`의 `data`입니다.

| 일 이름 | 요청에 더하는 값 | 하는 일 | 답 |
|---|---|---|---|
| `saveGeminiResult`(판독 결과 저장) | `{"record": 판독 결과 한 건}`. `images`와 `result`는 JSON 글입니다 | `gemini_results` 탭에 한 줄을 더합니다 | `{"saved": 1}` |
| `listGeminiResults`(검사의 판독 결과 읽기) | `{"inspection_id"}`. 빼면 모든 검사의 결과입니다 | `gemini_results` 탭을 읽습니다 | `{"results": [탭 줄, ...]}` |
| `runGemini`(OnePort로 Gemini 불러 판독) | `{"instruction": 지시문 글, "product_name": 제품 이름, "weight": 중량 글, "revision": 검사기준 버전, "standard": 검사기준 원문 글, "imageIds": [드라이브 파일 ID, ...]}` | 이 문서의 "실제 Gemini 판독" | 6항목 `{"판정": "OK", ...}` |
| `setOnePortKey`(OnePort 키 넣기) | `{"key"}` | 이 문서의 "OnePort 키" | `{"saved": true}` |

`gemini_results` 탭의 이름과 머리글, 시트 만들기(`setup`)에 더하는 일은 이 문서 "판독 결과와 저장"을 따릅니다.

서버가 사진의 드라이브 파일 ID를 보낼 때는 사진 주소 `/api/drive/(파일 ID)`(3회차 문서의 "서버가 Google을 쓰는 법")에서 꺼냅니다.

| 항목 | 약속 |
|---|---|
| 함께 쓰는 코드 | 서버와 Google 쪽이 함께 쓰는 코드(6항목 이름과 Gemini 답의 통과 검사)는 한 파일로 둡니다. 파일은 `shared/gemini-result.js`입니다 |
| 그 파일의 모양 | Google 쪽 코드 문법으로 쓰고, `module`이 있을 때만 `module.exports`로 내보냅니다. 서버는 이 파일을 실행할 때 `require`로 읽습니다. `tsconfig.json`의 `src` 밖에 있으므로 `dist` 폴더에서 한 칸 위로 찾습니다 |
| 올리기 | Google 쪽에 올릴 파일을 모으는 단계가 있으면 거기에 그 파일을 더합니다. 그런 단계가 없으면 `npm.cmd run gas:push`가 그 파일을 `gas` 폴더로 복사한 뒤 올리게 하고, 복사본은 Git에 올리지 않습니다(`.gitignore`) |
| 새 파일 | 새로 만든 Google 쪽 파일도 올릴 때 빠지지 않게 합니다 |
| 권한 설정 | Google 쪽 권한 설정(`appsscript.json`)은 바꾸지 않습니다(외부 연결 권한은 3회차에 넣었습니다) |

## 연습용 판독

`mock` 판독은 OnePort를 부르지 않고 만듭니다.

- 화면에 "판독 중"이 보이도록 1~2초 뒤에 끝나게 합니다.
- "판정"은 늘 `HOLD`입니다.
- 다른 항목에는 "[모의 테스트 초안]"과 지금 중량(없으면 미측정)을 넣습니다.

## 실제 Gemini 판독

4-18 단계를 수행할 때는 [단계 보충](steps/session-4/4-18.md)도 함께 읽습니다. 다른 번호의 기능은 앞당기지 않습니다.

실제 판독은 OnePort를 거쳐 Gemini 모델을 부릅니다. OnePort는 여러 AI 모델을 한 키로 부르게 해 주는 서비스이고, 요청과 답은 Chat Completions 모양입니다(문서: https://oneport.kr/docs ).

| 항목 | 약속 |
|---|---|
| 부르는 곳 | `live` 판독은 Google 쪽 코드(Apps Script)가 `UrlFetchApp`으로 `POST https://oneport.kr/v1/chat/completions`를 부릅니다 |
| 키 보내는 법 | 키는 Google 쪽 설정(스크립트 속성 `ONEPORT_API_KEY`, 이 문서의 "OnePort 키")에서 읽습니다. 키는 주소에 넣지 않고 `Authorization: Bearer (OnePort 키)` 머리글로 보냅니다. `contentType`은 `application/json`입니다. `muteHttpExceptions: true`를 주어 오류 코드를 직접 읽습니다 |
| 모델 | 요청의 `model`에 `gemini-3.8-flash`를 넣습니다. 이 모델 하나만 씁니다. 실패해도 다른 모델로 바꿔 보내지 않습니다 |
| 함께 보내는 것 | 고른 지시문, 검사 정보(제품 이름 또는 "제품 미지정", 중량 "352g" 또는 "미측정", 적용 검사기준 버전), 검사기준 원문, 드라이브에 있는 그 검사의 사진 |
| 요청 모양 | `{"model": "gemini-3.8-flash", "messages": [{"role": "user", "content": [글 조각, 사진 조각, ...]}], "response_format": {"type": "json_object"}, "max_tokens": 8192}`. `response_format`은 JSON 하나로만 답하게 하고, `max_tokens`는 답이 중간에 잘리지 않게 넉넉히 줍니다. 글 조각은 `{"type": "text", "text": 글}`이고 지시문, 검사 정보, 검사기준 원문을 담습니다. 사진 조각은 한 장에 하나씩 `{"type": "image_url", "image_url": {"url": "data:(사진 형식);base64,(사진 base64 글)"}}`입니다. 사진 형식은 드라이브 파일의 형식(예: `image/jpeg`)입니다 |
| 답하게 하는 모양 | 6항목 JSON으로만 답하게 합니다 |
| 답 읽기 | 답 글은 `choices[0].message.content`에 있습니다. 글 앞뒤에 코드 블록 표시(백틱 세 개, 그 뒤에 `json`이 붙기도 합니다)가 붙어 오면 떼고 JSON으로 읽습니다 |
| 사진 크기 | OnePort는 요청 본문이 4.5MB를 넘으면 받지 않습니다(코드 413). 사진은 base64 글로 바꾸면 약 4/3배로 커지므로, 보낼 사진의 원래 크기 합계가 3MB를 넘으면 부르지 않고 "사진이 너무 커서 판독할 수 없습니다."로 판독 실패를 남깁니다. 사진 크기를 줄이는 코드는 만들지 않습니다(학습 사진 저장소의 사진은 한 장 100KB 안쪽이라 여러 장이어도 3MB에 닿지 않습니다) |
| 통과 조건 | Gemini 답에 6항목이 모두 문자열로 있고 "판정"이 `OK`·`NG`·`HOLD` 중 하나면 통과이며, 그 밖의 키는 버립니다 |
| 통과하지 못하면 | 결과로 쓰지 않고 "판독 실패"와 이유를 남깁니다 |
| 다시 부르기 | 실패해도 저절로 다시 부르지 않습니다 |

OnePort가 오류를 돌려주면 판독 실패의 이유를 아래 문장으로 남깁니다. 오류 답의 본문은 `{"error": {"type": 종류, "message": 한국어 설명, "code": 오류 이름, "request_id": 요청 번호}}` 모양입니다.

| 코드 | 이유 |
|---|---|
| 401이고 `error`의 `reason`이 `key_revoked` | "이 OnePort 키는 꺼져 있습니다(코드 401). 강사에게 알려 주세요." |
| 그 밖의 401 | "OnePort 키가 맞지 않습니다(코드 401). 키를 다시 넣어 주세요." |
| 402 | "OnePort 잔액이 부족해 판독하지 못했습니다(코드 402). 강사에게 알려 주세요." |
| 403 | "이 OnePort 키로는 판독 모델을 쓸 수 없습니다(코드 403). 강사에게 알려 주세요." |
| 404 | "OnePort에서 판독 모델을 찾지 못했습니다(코드 404). 강사에게 알려 주세요." |
| 413 | "사진이 너무 커서 판독할 수 없습니다(코드 413)." |
| 429이고 `error`의 `code`나 `type`이 `key_limit_exceeded` | "OnePort 키의 사용 한도를 다 썼습니다(코드 429). 강사에게 알려 주세요." |
| 그 밖의 429(`rate_limit_error` 등), 500, 502, 503, 504 | "AI 판독 서버가 붐빕니다(코드 번호). 2분쯤 뒤 다시 눌러 주세요." 코드 번호 자리에 받은 번호를 적습니다 |
| 그 밖의 코드 | "OnePort 오류(코드 번호): " 뒤에 `error.message`를 그대로 붙입니다 |
| 답이 오지 않음(연결 실패, 시간 초과) | "OnePort에 연결하지 못했습니다. 2분쯤 뒤 다시 눌러 주세요." |

## 진행 상태와 잠금

| 항목 | 약속 |
|---|---|
| 진행 | 판독은 서버가 뒤에서 진행합니다 |
| 상태 기억 | 진행 상태("판독 중", "판독 실패")는 서버가 검사마다 기억합니다 |
| 2번 탭 | 열 때 그 상태를 묻고 판독 중이면 3초마다 다시 물어 끝나면 결과를 보여 줍니다. 상세 2번 탭은 주소 끝의 `?tab=2`로 엽니다 |
| 기다리는 시간 | 판독 한 번은 1~3분 걸릴 수 있으니 Google 쪽을 부를 때 그보다 짧게 끊지 않습니다. OnePort는 첫 응답까지 120초가 지나면 끊고, 그때는 "실제 Gemini 판독"의 오류 표대로 판독 실패를 남깁니다 |
| 서버를 다시 켜면 | 진행 중이던 "판독 중"·"판독 실패" 표시는 사라져도 됩니다(저장된 판독 결과는 남습니다) |
| 다른 요청 | OnePort를 부르는 동안 다른 요청을 막지 않습니다. Google 쪽 코드에 잠금(`LockService` 등)이 있으면 OnePort 부르기는 잠금 밖에서 하고, 그동안에도 2번 탭 상태 확인·홈·목록 요청은 바로 답합니다 |
| 등록하면 | 검사 등록이 끝나면 바로 판독을 시작합니다. 검사기준은 등록 때 고른 것, 지시문은 v3입니다. 판독 시작이 오류로 답하거나 판독이 실패해도 등록은 그대로 둡니다 |
| 등록 뒤 화면 | 등록이 끝나면 그 검사의 상세 2번 탭(`?tab=2`)을 엽니다 |
| 실제 판독 | `live`면 서버가 Google 쪽 일 `runGemini`(이 문서 "Google 쪽에 더할 일")를 불러 판독을 맡기고, 받은 6항목이 통과하면 판독 결과 한 건을 만들어 `saveGeminiResult`로 시트에 저장합니다 |

| 주소 | 하는 일과 요청 | 답 |
|---|---|---|
| `POST /api/inspections/(검사번호)/gemini` | 판독 시작. 요청은 `{"revision": 검사기준 버전, "prompt": 지시문 버전 이름}`이고 기다리지 않고 바로 답합니다. 빼면 검사기준은 등록 때 고른 것, 지시문은 v3입니다 | 아래 상태 |
| `GET /api/inspections/(검사번호)/gemini` | 2번 탭이 묻는 상태 | `{"mode": 판독 방식, "state": "idle"·"running"·"failed" 중 하나, "error": 실패 이유, "results": [판독 결과 한 건, ...], "stale": 가장 최근 결과가 "다시 판독 필요"면 true}`. `running`은 판독 중, `failed`는 판독 실패이고 `error`는 그때만 있습니다. `results`는 최근 것이 먼저입니다 |

두 주소 모두 검사가 없으면 "검사를 찾을 수 없습니다."입니다.

`GEMINI_MODE=off`이면 `POST`는 판독을 시작하지 않고 1회차 문서 "서버 오류 문장"의 오류 모양으로 "Gemini 판독이 꺼져 있습니다."를 답합니다. 진행 상태는 `failed`로 남기지 않아 `state`는 `idle` 그대로입니다. 등록할 때의 판독 요청이 이 오류를 받아도 등록은 그대로 마칩니다.

## 2번 탭

검사 상세 2번 탭("② AI 결과 확인")에 판독 결과를 보여 줍니다. 상태와 결과는 이 문서 "진행 상태와 잠금"의 `GET /api/inspections/(검사번호)/gemini`로 받습니다.

| 칸 | 약속 |
|---|---|
| 결과 6항목 | 가장 최근 판독 결과 하나를 보여 줍니다. 항목 이름은 "판정", "불량유형", "관찰·수치 근거", "적용 기준과 출처", "권고 조치", "사람 승인 필요 여부" 그대로 씁니다. 판정은 다른 항목보다 글자를 크게 하고, `OK`·`NG`·`HOLD`를 "정상"·"불량"·"보류"로 씁니다 |
| 결과가 없을 때 | "아직 판독한 결과가 없습니다."를 보여 줍니다 |
| 판독 버튼 | 성공한 판독 결과가 없으면 "AI 판독 요청", 하나라도 있으면 "AI 재판독 요청"입니다. 누르면 판독 시작(`POST`)을 부릅니다 |
| 판독 중 | `state`가 `running`이면 "판독 중"을 보여 주고, 3초마다 상태를 다시 물어 끝나면 결과를 다시 보여 줍니다 |
| 판독 실패 | `state`가 `failed`면 "판독 실패"와 `error`의 이유를 보여 줍니다 |
| 판독 시작이 거절될 때 | 판독 시작이 오류로 답하면(예: "Gemini 판독이 꺼져 있습니다.") 그 문장을 판독 버튼 가까이에 보여 줍니다 |
| 판독 조건 | 판독 버튼 옆에 검사기준(Rev.A·Rev.B)과 지시문을 고르는 칸을 둡니다. 지시문 목록은 설정 화면과 같습니다(이 문서 "원문 파일과 수정본"의 `GET /api/prompts`, 수정본 포함). 처음 값은 등록 때 고른 검사기준과 v3입니다. 고른 값을 판독 시작 요청의 `revision`, `prompt`로 보냅니다 |
| 판독 이력과 결과 비교 | 판독 결과가 두 개 이상이면 2번 탭 아래에 "판독 이력과 결과 비교" 칸을 둡니다. 고르는 칸 두 개에서 결과를 하나씩 고르고(결과마다 지시문 이름과 만든 시각으로 구분합니다), 고른 두 결과의 6항목을 나란히 보여 줍니다 |

결과 제목 옆에는 배지(작은 이름표)를 답니다. 위에서부터 먼저 맞는 것을 씁니다.

| 순서 | 경우 | 배지 |
|---|---|---|
| 1 | 판독 중 | "판독 중" |
| 2 | 판독 실패 | "판독 실패" |
| 3 | 판독 결과가 없음 | "결과 없음" |
| 4 | 가장 최근 결과가 "다시 판독 필요"(`stale`이 true) | "다시 판독 필요" |
| 5 | 그 밖 | "확인할 결과" |

## OnePort 키

수강생은 자기 OnePort 키를 이미 가지고 있습니다. 키를 새로 만드는 방법은 다루지 않습니다.

| 항목 | 약속 |
|---|---|
| 저장 위치 | OnePort 키(`ONEPORT_API_KEY`)는 `.env`와 Google 쪽 설정(Apps Script 스크립트 속성 `ONEPORT_API_KEY`)에만 둡니다 |
| 받는 법 | 사용자가 채팅으로 준 키를 `.env`의 `ONEPORT_API_KEY` 줄에 넣습니다. 같은 이름 줄이 있으면 값만 바꿉니다. 앞뒤에 공백이나 따옴표를 넣지 않습니다 |
| 넣는 법 | `npm.cmd run gas:init`이 하던 일을 마친 뒤 `setOnePortKey`로 `.env`의 키를 Google 쪽 설정에 넣습니다. 넣었으면 "OnePort 키를 넣었습니다.", `.env`에 키가 없으면 "OnePort 키가 .env에 없습니다."로 끝냅니다 |
| 키가 없을 때 | `live` 판독에서 Google 쪽 설정에 키가 없으면 OnePort를 부르지 않고 "OnePort 키가 없습니다."로 판독 실패를 남깁니다 |
| 내보내지 않기 | 키 값은 화면, 터미널, 로그 어디에도 내보내지 않습니다. OnePort에 보내는 `Authorization` 머리글도 로그와 판독 실패 이유에 적지 않습니다. 오류 이유에 붙이는 OnePort 설명에 `Bearer` 뒤의 글이나 키 값이 들어 있으면 그 부분을 `[가림]`으로 바꿉니다 |

## 다시 판독 필요와 검토 대기

**"다시 판독 필요"**: 판독 결과에 남긴 제품·중량·사진 목록이 지금 검사와 하나라도 다르면 그 결과는 "다시 판독 필요"입니다. 판단, 메모, 검사일시만 바뀐 것은 해당하지 않습니다.

- 2번 탭 상태 답의 `stale`이 이 기준을 씁니다.
- 가장 최근 결과가 "다시 판독 필요"면 2번 탭 배지를 "다시 판독 필요"로 바꾸고(이 문서 "2번 탭"의 배지 순서), 결과 위에 "검사 기록이 바뀌기 전의 결과입니다. 다시 판독해 주세요."를 띄웁니다.

**"검토 대기"(홈 "보고서 검토 대기")**: 성공한 판독 결과가 있고 아직 사람이 확인을 마치지 않은 검사입니다.

- 판독 결과가 없거나 실패만 한 검사는 세지 않습니다.
- 4회차에는 판독 결과가 있으면 모두 셉니다.
- 5회차에 출처 대조 기록이 생기면, 가장 최근 판독 결과가 "다시 판독 필요"가 아니고 그 결과의 마지막 대조 기록이 "일치"인 검사만 세지 않습니다.
- `GET /api/home`의 `review_pending`과 `GET /api/inspections`의 `review=pending`이 이 기준을 씁니다.

**Google 쪽 계산**: Google 저장일 때 홈 숫자나 카드 목록을 Google 쪽 코드가 계산하는 구조면, 그 계산도 시트의 판독 결과를 읽어 위 "검토 대기" 기준을 따릅니다.

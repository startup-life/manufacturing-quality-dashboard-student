# 1-7 보충: 로그인 화면 스크립트 제공

## 필요한 동작

로그인 화면의 HTML만 전달되고 `public/app.js`가 브라우저에 전달되지 않으면 로그인 버튼이 동작하지 않습니다. 이 단계에서 로그인 상자의 동작을 붙일 때 정적 파일 제공도 함께 확인합니다.

## 적용할 위치

`src/main.ts`에서 `express.static(path.join(process.cwd(), 'public'))`을 등록해 `/app.js`를 파일 그대로 제공합니다. 이 단계에서는 아직 로고를 만들지 않습니다. 정적 파일 처리기는 화면 주소를 `index.html`로 보내는 fallback보다 앞에 둡니다. `/api`는 fallback에서 제외하여 Nest 컨트롤러와 로그인 확인 처리가 계속 담당하게 합니다.

`public/index.html`의 스크립트 경로가 `/app.js`와 맞는지 확인합니다. 로그인 컨트롤러는 실패를 `{"error":"로그인 정보를 확인하세요."}`로 답하되 HTTP 상태를 200으로 보낼 수 있으므로, 화면은 `response.ok`만 보지 말고 응답 본문의 `error`가 있으면 실패로 처리합니다. 그래야 로그인 상자가 유지되고 오류 글이 보입니다. 별도 UI 기능이나 로그아웃 동작은 이 단계에서 추가하지 않습니다.

## 다시 확인

직전 단계(1-6) 완료 상태에서 서버를 켜고, Ego 브라우저에서 `/app.js`를 열어 JavaScript 파일 내용이 나오는지 확인합니다. `/`의 로그인 상자에서 틀린 비밀번호는 `로그인 정보를 확인하세요.`를 보여 주고 상자는 유지되어야 합니다. 올바른 비밀번호로 로그인하면 상자가 사라지고 `/api/abc`는 `요청한 주소를 찾을 수 없습니다.`를 보여야 합니다. 브라우저 콘솔에 `/app.js`의 404가 없어야 합니다.

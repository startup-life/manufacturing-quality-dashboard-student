# 1회차 보충 문서: 서버 뼈대와 로그인

이 문서는 AI 도구가 코드를 만들 때 읽는 자료입니다. 수강생은 이해하지 않아도 됩니다.

- 따로 부탁이 없으면 프롬프트가 말한 기능만 만듭니다. 프롬프트가 이 문서 전체를 가리켜도 같습니다. 사용자가 여러 기능을 한꺼번에 만들어 달라고 하거나 이 문서에 없는 일을 부탁하면 그대로 합니다.
- 앞 회차 문서와 다르면 번호가 큰 문서를 따릅니다. 이 회차가 바꾸는 앞 회차 약속은 없습니다(첫 문서입니다).
- 맨 끝의 끝 표시를 만들어 `AGENTS.md`가 말한 대로 답의 마지막 줄에 적습니다.

## 이번 회차가 끝나면 되는 것

`npm.cmd start`로 서버를 켜고 교육용 계정으로 로그인하고 로그아웃합니다. 로그인하면 각 주소에 빈 화면(품질 현황, 검사 등록, 검사 상세, 설정)이 하나씩 보이고, 없는 주소로 들어가면 안내가 나옵니다. 로그인하지 않으면 서버가 데이터를 주지 않습니다.

## 웹 서비스 뼈대

빈 웹 서비스 폴더에 처음 만드는 것입니다. 로그인, 머리 부분, 주소마다 다른 화면은 뒤 프롬프트에서 더하므로 여기서 만들지 않습니다.

- 프로그램: "추가 정보"의 프로젝트 설정 파일과 서버 코드 설정 파일을 웹 서비스 폴더 맨 위에 복사한 뒤 `npm.cmd install`로 받습니다. 함께 생기는 `package-lock.json`은 그대로 둡니다. 설치가 끝날 때 `vulnerabilities` 안내가 나와도 따로 부탁이 없으면 `npm audit fix`는 실행하지 않습니다.
- 서버: `npm.cmd start`로 켜지게 합니다("웹 서비스의 기본 약속"의 시작 명령). "웹 서비스의 기본 약속"의 포트와 켜질 때 안내를 따릅니다. 화면 파일은 "화면 주소"대로 보냅니다.
- 브라우저가 옛 화면을 기억하지 않게 서버의 모든 답에 `Cache-Control: no-store`를 붙입니다. 화면 파일을 고친 뒤 새로고침(F5)만 하면 고친 화면이 보이게 하려는 것입니다.
- 첫 화면: `public/index.html`에 큰 제목 "텀블러 공장 제조품질관리" 하나만 둡니다. 브라우저 탭 제목도 같은 글입니다. 어느 화면 주소로 들어와도 이 첫 화면이 나옵니다.
- 따로 부탁이 없으면 서버는 켜지 않고, `npm.cmd run build`로 오류가 없는지만 봅니다.

## 화면 서버 켜기

화면 서버를 켜거나 다시 켜는 일은 AI가 합니다. 사용자가 "화면 서버를 켜 주세요"나 "화면 서버를 다시 켜 주세요"라고 할 때 아래대로 합니다. `src` 폴더(서버 코드)나 `.env`를 고친 답을 할 때도 서버가 켜져 있었거나 서버를 켤 때 나온 오류를 고쳐 달라는 요청이었으면 아래대로 합니다. 고친 답에서는 먼저 `npm.cmd run build`로 오류가 없는지 봅니다.

서버는 `node --watch`로 켭니다("웹 서비스의 기본 약속"의 시작 명령). 빌드로 `dist` 폴더의 파일이 바뀌거나 `.env`가 바뀌면 서버가 같은 창에서 알아서 다시 켜지므로, 다시 켤 때는 빌드만 하면 됩니다. 서버 창은 하나만 둡니다. 사용자가 끄거나 새 창에서 켜 달라고 하면 아래 "끄기"와 "다시 켜기"대로 합니다.

- 시작 명령 확인: 웹 서비스 폴더의 `package.json`에서 `start`가 `node --watch --env-file-if-exists=.env dist/main.js`인지 봅니다. 다르면 이 값으로 고칩니다. 다시 켤 때 서버 창의 앞 줄은 지워지고 새로 찍힙니다. 완료 브랜치 코드의 `package.json`에 `--watch`가 없어도 이 값을 씁니다. 다시 켜는 데는 nodemon 같은 패키지가 필요 없습니다.
- 포트: "웹 서비스의 기본 약속"의 포트(4185)입니다. `.env`에 `PORT`가 있으면 그 값입니다.
- 켜져 있는지 보기: `Get-NetTCPConnection -LocalPort 4185 -State Listen -ErrorAction SilentlyContinue`를 실행합니다. 줄이 나오면 그 포트에서 요청을 받는 서버가 있는 것입니다.
- 감시 확인: `Get-CimInstance Win32_Process -Filter "Name='node.exe'" | Where-Object { $_.CommandLine -like '* --watch *dist/main.js*' } | Select-Object ProcessId, CommandLine`을 실행합니다. 줄이 나오면 서버 창에서 `--watch`로 도는 Node 프로세스가 있는 것입니다. 포트를 듣는 것은 이 프로세스가 띄운 서버이고, 이 프로세스는 서버가 오류로 멈춰도 창과 함께 남아 있습니다.
- 켜기: "다시" 없이 "켜 주세요"라는 요청에서 이미 켜져 있으면 새로 켜지 않고 "이미 켜져 있습니다"라고 알립니다. 포트가 비어 있어도 "감시 확인"에 줄이 나오면 서버 창이 오류로 멈춘 채 기다리는 중이니 새 창을 열지 않습니다. 먼저 아래 "오류 보기"대로 AI가 오류를 찾아(거기서도 원인이 보이지 않을 때만 서버 창의 빨간 줄을 붙여 넣어 달라고 합니다) 고친 뒤(고칠 것이 없으면 바로) `npm.cmd run build`를 해 그 창에서 다시 켭니다. 포트도 비어 있고 감시 확인에도 아무것도 나오지 않을 때만 AI가 명령을 실행하는 터미널이 아니라 새 PowerShell 창에서 켭니다. 서버가 꺼진 예전 서버 창이 남아 있으면 AI가 그 창의 PowerShell을 `taskkill /PID (번호) /T /F`로 끕니다(사용자가 닫아도 됩니다). 아래 명령을 PowerShell로 실행합니다. 새 창이 열리고 그 창에서 서버가 켜집니다. 앞부분은 새 창이 이 PC의 프로그램 경로를 다시 읽게 하는 줄입니다. 사용자가 AI 도구를 연 뒤에 설치한 프로그램(5회차의 nlm(NotebookLM을 부르는 도구) 등)도 서버가 찾게 하려는 것이므로 빼지 않습니다.

```powershell
Start-Process powershell -ArgumentList '-NoExit','-Command','$env:Path = [Environment]::GetEnvironmentVariable(''Path'',''Machine'') + '';'' + [Environment]::GetEnvironmentVariable(''Path'',''User''); cd C:\ai-class\tumbler-factory; npm.cmd start'
```

- 다시 켜기: "다시 켜 주세요"라는 요청이면 이미 켜져 있어도 "이미 켜져 있습니다"로 끝내지 않고 다시 켭니다. `npm.cmd run build`만 실행하면 됩니다. 사용자가 "끄고 새 창에서 켜 달라"고 하면 아래 "프로그램을 새로 설치한 뒤"처럼 끄고 새 창에서 켭니다. 빌드로 `dist` 폴더의 파일이 다시 써지면 서버가 같은 창에서 알아서 다시 켜집니다. 서버 창에 `Restarting`으로 시작하는 줄이 나온 뒤 `품질 대시보드 서버 실행 중: …`이 다시 나옵니다. 빌드하기 전에 포트를 듣는 프로세스 번호를 봐 두고, 빌드 뒤 몇 초 기다렸다가 그 번호가 바뀌었는지 봅니다. 바뀌었으면 다시 켜진 것이고, 포트가 비어 있으면 아래 "오류 보기"대로 AI가 오류를 찾아 고칩니다. 거기서도 원인이 보이지 않을 때만 서버 창의 빨간 줄을 붙여 넣어 달라고 합니다. 포트를 듣는 프로세스도 감시 확인에 나오는 프로세스도 없으면 서버가 꺼진 것이니 빌드 뒤 "켜기"로 켭니다.
- 프로그램을 새로 설치한 뒤: 프로그램(5회차의 nlm 등)을 새로 설치한 뒤 다시 켜 달라고 하면, 빌드로는 새 프로그램 경로를 읽지 못합니다. 이때는 감시 확인에 나온 프로세스와 포트를 듣는 프로세스를 끄고(사용자가 서버 창을 닫아도 됩니다), 포트와 감시 확인이 모두 빈 것을 확인한 뒤 "켜기"로 새 창에서 켭니다.
- 예전 방식으로 켠 서버: 포트를 듣는 서버는 있는데 "감시 확인"에 아무것도 나오지 않으면 `--watch` 없이 켠 서버라 알아서 다시 켜지지 않습니다. 이때는 "시작 명령 확인"대로 `package.json`을 고치고, 포트를 듣는 그 서버 프로세스를 끈 뒤(사용자가 서버 창을 닫아도 됩니다) 포트가 빈 것을 확인하고 "켜기"로 새 창에서 켭니다.
- 이 웹 서비스의 서버인지 보기: `Get-CimInstance Win32_Process -Filter "ProcessId=(OwningProcess 번호)" | Select-Object Name, CommandLine`으로 이름과 명령 줄을 봅니다. 이름이 `node.exe`이고 명령 줄에 이 웹 서비스 `package.json`의 `start` 명령이 켜는 파일(예: `dist/main.js`)이 들어 있으면 이 웹 서비스 폴더에서 켠 서버입니다. 아니면 그 프로그램 이름을 사용자에게 알리고 끌지 물어봅니다. 사용자가 끄라고 하면(그 프로그램을 끄라고 이미 말했으면 묻지 않고) 끄고 4185 포트로 켭니다.
- 켠 뒤: `npm.cmd start`는 빌드부터 하므로 켜지는 데 수십 초가 걸립니다. "켜져 있는지 보기"를 몇 초마다 다시 하면서 1분쯤 기다립니다(한 명령에 몰지 않고 20초 이하로 나눠 여러 번 실행합니다). 포트가 열리면 새 창(서버 창)에 `품질 대시보드 서버 실행 중: http://127.0.0.1:4185`가 나왔다고 알립니다. 서버 창의 글을 확인해야 하면 아래 "서버 창 글 확인"대로 AI가 봅니다. 1분이 지나도 열리지 않으면 새 창을 더 열지 않고, 아래 "오류 보기"대로 AI가 오류를 찾아 고칩니다. 거기서도 원인이 보이지 않을 때만 서버 창의 빨간 글이나 `error TS`가 들어 있는 줄을 복사해 보내 달라고 합니다. 고친 뒤 `npm.cmd run build`를 하면 서버가 그 창에서 다시 켜집니다. 그래도 포트가 열리지 않고 "감시 확인"에도 아무것도 나오지 않으면(빌드 오류로 서버 창이 명령 줄로 돌아간 경우) "켜기"로 새 창에서 켜고, 오류가 난 예전 창은 AI가 같은 방법으로 끕니다(사용자가 닫아도 됩니다).
- 서버 창 글 확인: AI는 서버 창의 글을 직접 볼 수 없습니다. 서버 창을 보는 일을 맡으면 아래 방법으로 보고, 그렇게 봤다고 답에 적습니다. 켜져 있는지는 "켜져 있는지 보기"로, 다시 켜졌는지는 포트를 듣는 프로세스 번호가 바뀌었는지로 봅니다. 켜질 때 찍는 줄(저장소, 연동 상태, 고칠 방법 한 줄)은 빌드 뒤 AI 터미널에서 다른 포트로 15초만 켜서 봅니다: `$env:PORT='4186'; $p = Start-Process node -ArgumentList '--env-file-if-exists=.env','dist/main.js' -NoNewWindow -PassThru; Start-Sleep 15; if (!$p.HasExited) { Stop-Process -Id $p.Id }; Remove-Item Env:PORT`. 4185 서버는 그대로 둡니다.
- 오류 보기: 서버 창의 오류는 AI가 먼저 찾습니다. AI가 명령을 실행하는 터미널에서 `npm.cmd run build`로 빌드 오류를 봅니다. 빌드 오류가 없고 빌드 뒤 10초 기다려도 포트가 비어 있으면, 서버를 켤 때의 오류를 15초 뒤 저절로 끝나게 실행해 봅니다: `$p = Start-Process node -ArgumentList '--env-file-if-exists=.env','dist/main.js' -NoNewWindow -PassThru; Start-Sleep 15; if (!$p.HasExited) { Stop-Process -Id $p.Id }`. 그사이 포트가 열렸으면 그 프로세스는 이미 끈 것이니, 서버 창에서 다시 켜지도록 `npm.cmd run build`를 합니다.
- `EADDRINUSE`: 다른 프로세스가 이미 그 포트를 쓰는 것입니다. 사용자가 이 글을 붙여 넣으면 그 포트의 프로세스가 이 웹 서비스의 서버인지 봅니다. 이 웹 서비스의 서버면 먼저 켠 서버 창이 따로 있는 것이니, 그 창을 그대로 쓰고 `EADDRINUSE`가 나온 창은 닫아도 된다고 알립니다. 사용자가 맡기면, 명령 줄에 `npm.cmd start`가 든 powershell.exe 가운데 포트를 듣는 서버를 띄우지 않은 쪽(`EADDRINUSE`가 나온 창)을 `taskkill /PID (번호) /T /F`로 끕니다. 창과 그 안의 프로세스가 함께 꺼집니다. 아니면 무엇이 그 포트를 쓰는지 사용자에게 알리고 끌지 물어봅니다. 사용자가 끄라고 하면(그 프로그램을 끄라고 이미 말했으면 묻지 않고) 끄고 4185 포트로 켭니다.
- 끄기: 사용자가 서버 창을 닫거나 그 창에서 Ctrl+C를 누르면 꺼집니다. "일괄 작업을 끝내시겠습니까 (Y/N)?"가 나오면 `Y`를 칩니다. AI가 끌 때는 명령 줄에 `npm.cmd start`가 든 powershell.exe(서버 창)를 `taskkill /PID (번호) /T /F`로 끕니다. 창과 그 안의 프로세스가 함께 꺼집니다. 그다음 포트와 감시 확인이 모두 빈 것을 보고, 남은 것이 있으면 `Stop-Process -Id (번호)`로 끕니다.

## 오래 걸리는 명령

AI 도구에 따라서는 AI가 실행하는 명령에 아래 제한이 있습니다. 이 절의 방법은 어느 AI 도구에서나 그대로 씁니다.

- 명령 하나가 30초를 넘으면 그 명령과 그 명령이 띄운 프로그램을 함께 강제로 끝냅니다. 그때까지 나온 글은 AI에게 가지 않고 시간 초과 오류만 갑니다.
- 명령마다 새 PowerShell이 뜹니다. 앞 명령의 `cd`, `$env:Path`, 변수는 다음 명령에 남지 않습니다. 한 번에 여러 명령을 보내면 동시에 실행됩니다.
- 명령에는 입력을 넣을 수 없습니다. y/n이나 값을 묻는 질문에 답하지 못합니다.
- 프로그램 경로는 AI 도구를 켤 때 정해집니다. 그 뒤에 설치한 프로그램은 경로를 다시 읽어야 찾을 수 있습니다.
- AI에게는 명령 결과 하나마다 앞뒤를 합쳐 8,000자쯤(앞 4,000자, 뒤 4,000자쯤)만 가고 가운데는 빠집니다.
- `Start-Process`로 새 창을 띄우고 바로 끝나는 명령은 30초 제한에 걸리지 않고, 새 창은 그대로 남습니다. 같은 명령 안에서 새 창을 기다리면 30초에 새 창까지 함께 꺼집니다. 서버를 켜는 명령(이 문서의 서버 켜기 절)이 새 창을 띄우고 바로 끝나는 것도 이 때문입니다.
- 실행 중인 명령을 떼어 계속 돌리는 단추가 AI 도구에 있어도 사용자에게 누르라고 하지 않고, 이 절의 새 창 방식으로 합니다.

### 한 명령에 담기

- 명령은 한 번에 하나씩 보냅니다. 순서가 있는 명령은 한 명령 안에 `;`로 잇습니다. `&&`는 PowerShell 판에 따라 문법 오류가 나므로 쓰지 않습니다. 이어 쓴 명령이 합쳐서 30초를 넘길 수 있으면 하나씩 따로 보내거나 아래 "새 창에서 실행하기"로 합니다.
- `;`로 이은 뒤 명령은 앞 명령이 실패해도 실행됩니다. 앞 명령이 성공해야 하는 명령(올리기 뒤 배포 등)은 잇지 않고 따로 보내, 결과를 본 뒤 다음을 보냅니다.
- 다른 폴더에서 할 명령은 그 명령 앞에 `cd '(폴더 전체 경로)';`를 둡니다. 따로 보낸 `cd`는 다음 명령에 남지 않습니다.
- 경로 다시 읽기: `ego-browser`를 부르는 명령과 이 대화에서 설치한 프로그램을 부르는 명령에는 늘 맨 앞에 아래 줄을 붙이고 `<명령>` 자리에 부를 명령을 넣습니다. 그 밖의 명령도 찾지 못하면 이 줄을 붙여 다시 실행합니다. 이 줄만 따로 실행하면 다음 명령에 남지 않습니다. 그래도 찾지 못하면 그 프로그램 실행 파일의 전체 경로로 부릅니다.

```powershell
$env:Path = [Environment]::GetEnvironmentVariable('Path','Machine') + ';' + [Environment]::GetEnvironmentVariable('Path','User'); <명령>
```

- 외부 프로그램에 넘기는 글: `curl.exe`, `git`, `ego-browser` 같은 외부 프로그램의 인자 안에 큰따옴표를 넣지 않습니다. PowerShell 판에 따라 큰따옴표가 사라집니다. 외부 프로그램에 파이프(`|`)로 한글을 넘기지도 않습니다. 판에 따라 `?`로 바뀝니다. 큰따옴표가 든 글(JSON 본문 등)과 브라우저 스크립트는 AI 도구의 파일 쓰기로 파일에 저장한 뒤 파일로 넘깁니다. 예: `curl.exe`의 본문은 `--data-binary '@(파일 전체 경로)'`, 브라우저 스크립트는 아래 "ego 브라우저"의 꼴. `npm.cmd`처럼 `.cmd`로 설치된 명령도 같습니다. 작은따옴표로 감싼 인자 속 한글(예: `git commit -m '고친 내용'`)은 이 규칙에 들지 않습니다.
- 묻는 명령: 묻지 않게 하는 옵션을 붙입니다. 예: `npx --yes`, `Remove-Item -Force`, `winget install (이름) --accept-source-agreements --accept-package-agreements`.
- `2>&1`: `git`, `npm.cmd` 같은 프로그램의 출력에 `2>&1`이나 `2>(파일)`을 붙이면 경고 한 줄에도 명령이 멈출 수 있습니다. 붙여야 하면 같은 명령 맨 앞에 `$ErrorActionPreference='Continue';`를 둡니다.
- 출력 줄이기: 출력이 길 것 같으면 `| Select-Object -Last 40`이나 `| Select-String '(찾을 글)'`을 붙여 필요한 줄만 봅니다. 파일 전체를 봐야 하면 아래 "긴 출력 읽기"대로 합니다.

### 새 창에서 실행하기

아래 명령은 새 창에서 실행합니다. 빌드나 확인처럼 몇 초면 끝나는 명령만 AI가 명령을 실행하는 터미널에서 합니다. 서버를 켜는 일은 이 절이 아니라 이 문서의 서버 켜기 절을 따릅니다.

- 설치: 프로그램 설치, `npm.cmd install`, `npx`로 패키지를 처음 내려받는 명령. 설치는 늘 새 창에서 합니다.
- 30초를 넘길 수 있는 그 밖의 명령: 큰 저장소의 clone이나 첫 fetch, 회차 문서가 새 창에서 하라고 한 명령
- 로그인이 끝날 때까지 기다리는 명령: `gas:login` 같은 로그인 명령, `git push`(처음 올릴 때 Git 로그인 창이 뜨고 기다립니다)
- AI가 명령을 실행하는 터미널에서 30초에 끊긴 적이 있는 명령

`<명령>` 자리에 그 명령을 넣어(꺾쇠도 지웁니다) 실행합니다.

```powershell
Remove-Item $env:TEMP\ai-cmd.log -ErrorAction SilentlyContinue; (Start-Process powershell -PassThru -WorkingDirectory (Get-Location).Path -ArgumentList '-Command','$env:Path = [Environment]::GetEnvironmentVariable(''Path'',''Machine'') + '';'' + [Environment]::GetEnvironmentVariable(''Path'',''User''); [Console]::OutputEncoding = [Text.Encoding]::UTF8; & { <명령> 2>&1; ''AI-CMD-END:'' + $LASTEXITCODE } | ForEach-Object ToString | Tee-Object -FilePath $env:TEMP\ai-cmd.log').Id
```

- 이 명령은 이전 출력 파일을 지우고 새 창을 연 뒤 그 창의 프로세스 번호만 보여 주고 바로 끝납니다. 그래서 이 명령에는 기다리기나 확인을 붙이지 않습니다. 보여 준 번호는 끝났는지 볼 때 씁니다.
- 새 창은 경로를 다시 읽은 뒤 명령을 실행하므로, AI 도구를 연 뒤 설치한 프로그램도 찾습니다.
- `<명령>`에 든 따옴표는 큰따옴표든 작은따옴표든 모두 작은따옴표 두 개(`''`)로 바꿔 씁니다. 큰따옴표를 그대로 두면 새 창에 닿기 전에 사라집니다. 예: uv 설치는 `powershell -ExecutionPolicy ByPass -c ''irm https://astral.sh/uv/install.ps1 | iex''`입니다.
- `<명령>`에 `$env:…`를 넣지 말고, 그 값을 먼저 실행해 얻은 뒤 풀어 적습니다.
- 새 창은 이 명령을 실행한 폴더에서 시작합니다. 다른 폴더에서 실행해야 하면 `(Get-Location).Path`를 `'(폴더 전체 경로)'`로 바꿉니다.
- 환경 변수가 필요하면 같은 줄의 `Start-Process` 앞에 `$env:이름='값';`으로 둡니다.
- 새 창은 명령이 끝나면 저절로 닫힙니다. 출력은 `$env:TEMP\ai-cmd.log`에 남고, 마지막 줄에 `AI-CMD-END:(종료 코드)` 줄이 찍힙니다.
- 새 창에서 실행하는 명령은 한 번에 하나만 띄웁니다. 같은 출력 파일을 쓰므로, 앞 명령의 `AI-CMD-END` 줄을 본 뒤 다음 명령을 띄웁니다.

### 끝났는지 보기

아래 명령으로 15초 기다린 뒤 출력 파일의 끝 30줄을 봅니다. 한 번에 20초를 넘지 않으므로 `AI-CMD-END` 줄이 나올 때까지 이 명령을 되풀이합니다.

```powershell
Start-Sleep -Seconds 15; if (Test-Path $env:TEMP\ai-cmd.log) { Get-Content $env:TEMP\ai-cmd.log -Tail 30 } else { '아직 출력 파일이 없습니다' }
```

- `ai-cmd.log`는 AI 도구의 파일 읽기로 열지 않고 위 명령의 `Get-Content`로만 봅니다. 더 보려면 `-Tail` 숫자를 늘립니다.
- 마지막 줄이 `AI-CMD-END:0`이면 명령이 끝난 것입니다. 성공했는지는 그 위 글을 그 명령의 성공 기준과 맞춰 봅니다. 회차 문서에 성공 기준이 있으면 그 기준을 씁니다.
- `AI-CMD-END:` 뒤가 0이 아닌 숫자면 실패입니다. 그 위 글로 원인을 봅니다.
- `AI-CMD-END:` 뒤가 비어 있으면 종료 코드를 남기지 않는 PowerShell 명령입니다. 그 위 글로 성공했는지 봅니다.
- `AI-CMD-END` 줄이 없으면 새 창을 열 때 나온 번호로 아래 명령을 실행합니다. "실행 중"이면(출력 파일이 아직 없어도 첫 출력 전입니다) 새 창을 다시 띄우지 않고 위 확인을 되풀이합니다. "창이 닫혔습니다"면 창이 중간에 닫힌 것입니다. 그 위 글을 보고, 아래 "시간 초과로 끊겼을 때"처럼 결과가 이미 생겼는지 먼저 본 뒤 필요할 때만 다시 실행합니다.

```powershell
if (Get-Process -Id (번호) -ErrorAction SilentlyContinue) { '실행 중' } else { '창이 닫혔습니다' }
```

- 로그인을 기다리는 명령이 아닌데 10번(약 3분) 확인해도 로그 끝이 그대로면, 새 창이 무엇을 묻고 멈췄을 수 있습니다. 새 창에 보이는 글을 알려 달라고 하고 답을 끝냅니다.
- 로그인을 기다리는 명령은 아래 "사용자에게 넘기는 일"대로 합니다.

### 기다리기

- 문서나 따라하기에 "1분 기다린다"처럼 긴 기다림이 있으면 `Start-Sleep -Seconds 20` 이하로 나눠 여러 번 실행합니다. 기다린 뒤 확인까지 한 명령에 담으면 합쳐서 20초 이하로 합니다. 예: `Start-Sleep -Seconds 15; (확인 명령)`.
- 무엇이 생길 때까지 되풀이하는 고리(`while` 등)를 한 명령에 쓰지 않습니다. 확인 명령을 여러 번 보냅니다.

### 시간 초과로 끊겼을 때

- 30초에 끊긴 명령은 시간 초과 오류만 남고 출력은 오지 않습니다. 실패가 아니라 어디까지 됐는지 모르는 상태입니다.
- 다시 실행하기 전에 그 명령의 결과가 이미 생겼는지 먼저 봅니다. 예: 만들어진 파일이나 폴더, 설치된 명령의 버전, Apps Script 배포 목록, 시트의 끝 줄.
- 결과가 생겼으면 다시 실행하지 않습니다. 생기지 않았으면 "새 창에서 실행하기"로 다시 실행합니다. 설치가 중간에 끊겼으면 새 창에서 같은 설치를 다시 실행합니다.
- ego 브라우저에서 단추를 누르는 실행이 끊겼을 때도 같습니다. 같은 단추를 다시 누르기 전에 결과가 생겼는지 먼저 봅니다.

### 긴 출력 읽기

- 출력이 8,000자를 넘을 것 같으면(긴 파일을 `git --no-pager show`로 읽을 때 등) 파일로 저장합니다. 마지막 부분은 저장한 파일의 전체 경로를 보여 줍니다.

```powershell
[Console]::OutputEncoding = [Text.Encoding]::UTF8; <명령> | Out-File -Encoding utf8 -FilePath "$env:TEMP\ai-out.txt"; "$env:TEMP\ai-out.txt"
```

- 저장한 파일은 AI 도구의 파일 읽기로, 위 명령이 보여 준 전체 경로를 열어 읽습니다. 한 번에 다 나오지 않으면 나눠 읽습니다.
- 파일 읽기로 열지 못하면 아래 명령으로 7,000자씩 읽습니다. 처음에는 `$s = 0`이고, 다음 조각은 `7000`, `14000`처럼 7,000씩 늘립니다.

```powershell
$s = 0; $t = Get-Content -Raw -Encoding UTF8 "$env:TEMP\ai-out.txt"; $t.Substring($s, [Math]::Min(7000, $t.Length - $s))
```

### ego 브라우저

- 이 대화에서 ego 브라우저를 처음 쓸 때 아래 명령으로 사용법 안내를 파일로 저장하고, "긴 출력 읽기"대로 첫 줄부터 `[ego-browser:skill] end of guide`로 시작하는 끝 줄까지 읽습니다. 안내를 명령 출력으로 바로 보면 가운데가 빠져도 끝 줄은 남아서 다 읽은 것처럼 보이므로, 꼭 파일로 읽습니다. 이 대화에서 이미 읽었으면 다시 읽지 않습니다.

```powershell
$env:Path = [Environment]::GetEnvironmentVariable('Path','Machine') + ';' + [Environment]::GetEnvironmentVariable('Path','User'); [Console]::OutputEncoding = [Text.Encoding]::UTF8; ego-browser skill | Out-File -Encoding utf8 -FilePath "$env:TEMP\ego-browser-skill.md"; "$env:TEMP\ego-browser-skill.md"
```

- 스크립트는 파일로 넘깁니다. `-e`로 인자에 넣거나 파이프(`|`)로 넘기지 않습니다. 먼저 `$env:TEMP`를 실행해 임시 폴더의 전체 경로를 보고, AI 도구의 파일 쓰기로 `(그 전체 경로)\ego-script.js`에 UTF-8로 저장합니다. 파일 쓰기에 `$env:TEMP`나 `%TEMP%`를 글자 그대로 쓰지 않습니다. 그 글자 이름의 폴더가 작업 폴더 안에 생깁니다.
- 첫 실행은 아래처럼 TaskSpace(작업 공간)를 만들고 그 번호를 찍습니다. 다음 실행부터는 `taskSpace("(작업 이름)")` 대신 찍힌 번호로 `await taskSpace((번호))`를 씁니다. 다음 답에서 같은 일을 이어 갈 때는 사용법 안내의 "Starting and ending a reply"대로 그 번호로 잇습니다.

```javascript
const task = await taskSpace("(작업 이름)");
const page = task.page("p1");
await page.goto("(주소)", { timeout: 15000 });
console.log({ taskSpaceId: task.spaceId });
console.log(String(await page.snapshot()).slice(0, 7000));
```

- 그다음 아래 명령으로 실행합니다. 실행이 끝나면 스크립트 파일을 지우고 ego 브라우저의 종료 코드를 찍습니다. 스크립트를 바꿀 때마다 파일을 다시 저장하고 이 명령을 다시 실행합니다.

```powershell
$env:Path = [Environment]::GetEnvironmentVariable('Path','Machine') + ';' + [Environment]::GetEnvironmentVariable('Path','User'); [Console]::OutputEncoding = [Text.Encoding]::UTF8; cmd /c "ego-browser nodejs < %TEMP%\ego-script.js"; $c = $LASTEXITCODE; Remove-Item $env:TEMP\ego-script.js; "ego-browser 종료 코드: $c"
```

- 한 번 실행은 20초 안에 끝나게 합니다. 한 실행에는 동작 하나와 짧은 확인만 담고, 한 실행 안의 `timeout`을 모두 더해 15초(15000) 이하로 줍니다.
- 찍는 글도 8,000자를 넘으면 가운데가 빠집니다. 위 예처럼 `.slice(0, 7000)`으로 자르고, 더 봐야 하면 `.slice(7000, 14000)`처럼 다음 실행에서 이어서 찍습니다.
- 몇 분 걸리는 일(처리 결과 기다리기, 학습 등)은 단추를 누르는 실행과 결과를 보는 실행을 나누고, 결과 보기를 20초 이하로 여러 번 합니다.
- 사람이 브라우저에서 해야 하는 순간이 오면 `await task.handOff()` 뒤 그 실행을 끝내고, 무엇을 하면 되는지 한 줄로 알린 뒤 답을 끝냅니다. `waitForControl()`로 같은 실행 안에서 기다리지 않습니다. 사용자가 마쳤다고 하면 `const task = await takeOverTaskSpace((번호));`로 같은 작업 공간을 이어받고, `task.userPage()`로 사용자가 보던 페이지를 씁니다.

### 사용자에게 넘기는 일

- 사람이 해야 하는 순간의 예: 비밀번호와 본인 확인 같은 로그인 단계, 사용자 계정 컨트롤(설치 승인 창), Git 로그인 창이나 로그인 명령이 연 Chrome 창처럼 AI가 누를 수 없는 창.
- 로그인 명령의 출력("끝났는지 보기" 명령으로 본 글)에 로그인 주소가 나오면 그 주소를 ego 브라우저에서 열어 AI가 할 수 있는 데까지 합니다. 비밀번호, 본인 확인, AI가 누를 수 없는 창에서만 할 일을 알리고 답을 끝냅니다.
- 그 순간을 만드는 명령은 "새 창에서 실행하기"로 띄우고, 브라우저 안의 일은 `task.handOff()`로 넘깁니다. 그다음 무엇을 하면 되는지 한 줄로 알리고 답을 끝냅니다. 한 명령 안에서 사람이 마치기를 기다리지 않습니다.
- 사용자가 마쳤다고 하면 "끝났는지 보기"나 그 일의 확인 명령으로 보고 이어서 합니다.

## 화면 주소

- 화면은 `public/index.html` 한 페이지입니다.
- `/api`로 시작하지 않는 주소는 `public` 폴더에 그 파일이 있으면 그 파일을, 없으면 `index.html`을 보냅니다. 어느 화면을 보여 줄지는 화면 쪽에서 주소를 보고 정합니다.
- 이 처리는 `src/main.ts`의 미들웨어로 둡니다. `public` 폴더의 파일 제공(`express.static`)을 먼저 두고, 그 뒤에 `/api`로 시작하는 요청은 다음 처리로 넘기고 나머지 주소에는 `sendFile`로 `index.html`을 보내는 미들웨어를 둡니다. NestJS 컨트롤러의 와일드카드 주소로는 만들지 않습니다.
- 화면 글은 모두 한국어입니다.

| 화면 주소 | 화면 이름 |
|---|---|
| `/` | 품질 현황(홈) |
| `/inspections/new` | 검사 등록 |
| `/inspections/(검사번호)` | 검사 상세 |
| `/settings` | 설정 |

- 로그인 전에는 주소와 상관없이 "로그인 화면"의 로그인 상자만 보입니다. 화면 내용, 머리 오른쪽, 노란 안내, 바닥글은 숨깁니다.
- 로그인한 뒤에는 주소에 맞는 화면 하나만 보입니다. 이 회차의 각 화면에는 위 표의 화면 이름만 제목으로 둡니다(홈은 "품질 현황"). 내용은 뒤 회차에서 채웁니다.
- 위 표에 맞는 화면이 없는 주소는 "페이지를 찾을 수 없습니다"와 "홈으로 가기" 버튼을 보여 줍니다. 버튼을 누르면 홈(`/`)으로 갑니다.
- 사이트 안 링크(머리 부분의 로고와 웹 서비스 이름, "설정", "홈으로 가기")를 누르면 페이지를 새로 불러오지 않고 주소와 화면만 바꿉니다(브라우저 방문 기록에 주소를 더함). 브라우저의 뒤로·앞으로 가기를 누르면 그 주소에 맞는 화면으로 바뀝니다.

## 서버 오류 문장

- 화면이 쓰는 데이터 주소는 `/api`로 시작합니다.
- 로그인 전 거절은 "로그인"을 따릅니다.
- 오류가 나면 `{"error": "한국어 문장"}` 모양으로 답하고 화면은 그 문장을 그대로 보여 줍니다.
- 오류 문장은 세 가지로 나눕니다. 모두 같은 `{"error": "한국어 문장"}` 모양입니다.

| 경우 | 문장 |
|---|---|
| 없는 `/api` 주소 | 로그인한 사람에게는 "요청한 주소를 찾을 수 없습니다."로 답합니다. 이 경우에만 이 문장을 씁니다. 서버 틀이 기본으로 내는 영어 답(`Cannot GET ...`)을 그대로 보내지 않습니다 |
| 코드가 일부러 낸 오류 | 그 문장을 바꾸지 않고 그대로 보냅니다. 예: "검사를 찾을 수 없습니다." |
| 예상하지 못한 오류 | 한국어 한 줄로 바꿉니다 |

## 로그인

- 로그인 상태는 `express-session`으로 서버 메모리에 저장합니다. 서버를 다시 켜면 로그인이 풀려도 됩니다.
- 로그인 데이터 주소는 아래 셋입니다. 이 셋을 제외한 `/api` 주소는 로그인한 사람에게만 답합니다. 로그인 전이면 없는 주소라도 `{"error": "로그인이 필요합니다."}`로 답합니다.

| 주소 | 하는 일 |
|---|---|
| `GET /api/session` | 로그인 상태를 답합니다. 로그인 전이면 `{"user": null}`, 로그인 뒤면 `{"user": {"username": 계정, "role": 역할 값}}`입니다 |
| `POST /api/login` | 로그인합니다. 요청은 `{"username": 계정, "password": 비밀번호}`이고 성공하면 `GET /api/session`과 같은 모양으로 답합니다. 계정이나 비밀번호가 틀리면 `{"error": "로그인 정보를 확인하세요."}`로 답합니다 |
| `POST /api/logout` | 로그아웃합니다. `{"user": null}`로 답합니다 |

- `POST /api/login`은 화면이 보낸 JSON 본문에서 계정과 비밀번호를 읽습니다. 로그인은 사용자가 브라우저에서 확인하므로 "웹 서비스의 기본 약속"의 서버 칸대로 컨트롤러로 만들어 본문이 읽히게 합니다.

교육용 계정입니다. 역할 값은 계정 이름과 같습니다. 화면에는 계정을 오른쪽 칸에 적힌 한국어로 표시합니다.

| 계정 | 비밀번호 | 화면 글 |
|---|---|---|
| `writer` | `writer1234!` | 작성자 |
| `reviewer` | `reviewer1234!` | 검토자 |
| `factory-user` | `factory1234!` | 품질관리 |

## 로그인 화면

- 로그인 상자 맨 위에 첫 화면의 큰 제목 "텀블러 공장 제조품질관리"를 두고, 그 아래에 계정 칸, 비밀번호 칸, "로그인" 버튼을 둡니다.
- 칸의 처음 값은 계정 `writer`, 비밀번호 `writer1234!`입니다. 비밀번호는 가려서 표시합니다.
- 페이지를 열면 `GET /api/session`으로 로그인 상태를 묻습니다. 이미 로그인했으면 로그인 상자를 바로 숨깁니다.
- "로그인" 버튼을 누르면 `POST /api/login`으로 로그인합니다. 성공하면 로그인 상자를 숨기고 지금 주소에 맞는 화면을 보여 줍니다. 실패하면 서버가 보낸 문장(예: "로그인 정보를 확인하세요.")을 로그인 상자 안에 빨간 글로 보여 주고 상자는 그대로 둡니다. 응답 본문에 `error`가 있는지 보고 실패 여부를 정합니다. 로그인 실패도 성공 상태 번호(2xx)로 올 수 있어 `response.ok`만으로는 구분할 수 없습니다.
- 머리 부분의 "로그아웃" 버튼을 누르면 `POST /api/logout`으로 로그아웃하고 로그인 상자를 다시 보여 줍니다. 이때 계정 칸과 비밀번호 칸을 처음 값으로 되돌리고, 빨간 글은 지웁니다. 머리 오른쪽, 노란 안내, 바닥글, 화면 내용은 숨깁니다.
- 로그인 전 첫 화면과 로그아웃 직후에는 새로고침하지 않아도 머리 오른쪽("설정", 사용자 표시, "로그아웃")이 보이지 않아야 합니다. 숨김을 `hidden` 속성으로 하면 CSS에서 지정한 `display`(예: `display: flex`)가 그 숨김을 덮지 않는지 확인합니다. 로그아웃할 때 사용자 표시 글자도 비웁니다.

## 화면 맨 위 줄

- 이 문서와 뒤 회차 문서는 이 줄을 "머리 부분"이라고 부릅니다.
- 화면 맨 위에 한 줄로 둡니다.
- 왼쪽: 로고 그림과 웹 서비스 이름 "텀블러 공장 제조품질관리". 둘 다 누르면 홈(`/`)으로 갑니다. 로그인 전에도 보여도 됩니다(로그인 전 화면에서 웹 서비스 이름이 머리 부분과 로그인 상자에 두 번 보여도 됩니다).
- 로고 그림: 텀블러 공장을 떠올리게 하는 단순한 그림 파일을 AI가 직접 그려 `public` 폴더에 둡니다(예: `public/logo.svg`). 글자 없이 도형 몇 개와 색 두세 가지로만 그립니다. 모양은 자유입니다.
- 오른쪽(로그인한 뒤에만 보임): "설정" 링크(`/settings`로 감), 사용자 표시, "로그아웃" 버튼.
- 이 줄을 만드는 요청에서는 오른쪽 세 가지("설정" 링크, 사용자 표시, "로그아웃" 버튼)를 모두 화면에 둡니다. 프롬프트에 "웹 서비스 이름과 내 계정"만 적혀 있어도 "설정" 링크와 "로그아웃" 버튼을 빼지 않습니다. 이 둘은 이 줄의 일부이고 뒤 번호 기능이 아닙니다.
- "로그아웃 동작은 다음 번호에서 만듭니다"는 버튼을 눌렀을 때의 동작("로그인 화면"의 로그아웃)만 뒤로 미룬다는 뜻입니다. 지금은 눌러도 아무 일도 하지 않는 "로그아웃" 버튼을 둡니다. "설정" 링크도 `/settings`로 가는 링크만 두고, 그 주소의 화면과 새로고침 없이 화면을 바꾸는 기능은 뒤 번호에서 만듭니다.
- 사용자 표시는 `계정 (화면 글)` 형식입니다. 예: "writer (작성자)", "reviewer (검토자)", "factory-user (품질관리)". 화면 글은 "로그인"의 계정 표를 따릅니다.

## 노란 안내와 바닥글

- 로그인한 뒤에만 보입니다. 로그인 전과 로그아웃한 뒤에는 숨깁니다.
- 노란 안내: 머리 부분 바로 아래에 노란 바탕의 안내 상자를 두고, "추가 정보"의 노란 안내 글을 글자 그대로 넣습니다.
- 바닥글: 화면 맨 아래에 "텀블러 공장 품질관리 시스템입니다."를 둡니다.

## 추가 정보

프롬프트에서 말하는 "이번 회차 추가 정보"는 아래 표의 파일입니다. 파일은 `docs/guide/files/`에 있고 프롬프트가 가리킬 때 엽니다.

- `copy` 폴더: 파일을 그대로 웹 서비스 폴더에 넣습니다. 글자를 바꾸지 말고 복사합니다.
- `reference` 폴더: AI가 읽고 코드나 화면에 씁니다. 그대로 웹 서비스 폴더에 복사하지 않습니다.

| 프롬프트에서 부르는 이름 | 종류 | 파일 | 쓰는 법 |
|---|---|---|---|
| 프로젝트 설정 파일 | 복사 | `docs/guide/files/copy/package.json` | 웹 서비스 폴더 맨 위에 `package.json`으로 복사합니다. 패키지 버전은 이 파일로 고정합니다 |
| 서버 코드 설정 파일 | 복사 | `docs/guide/files/copy/tsconfig.json` | 웹 서비스 폴더 맨 위에 `tsconfig.json`으로 복사합니다 |
| 노란 안내 글 | 참고 | `docs/guide/files/reference/yellow-notice.md` | 파일에 적힌 한 줄을 글자 그대로 화면에 넣습니다 |

## 만들지 않는 것

아래 기능은 혼자 쓰는 연습용 웹 서비스라 기본으로는 만들지 않습니다. 사용자가 부탁하면 만듭니다.

- 요청마다 보안 확인 값(CSRF 토큰)을 주고받아 검사하는 기능: 혼자 쓰는 연습용 웹 서비스라 기본으로는 만들지 않습니다.
- 보안 머리글을 더하는 기능(helmet 같은 패키지): 혼자 쓰는 연습용 웹 서비스라 기본으로는 만들지 않습니다.
- 다른 사이트에서 온 요청(Origin 머리글)을 거절하는 검사: 혼자 쓰는 연습용 웹 서비스라 기본으로는 만들지 않습니다.
- 세션 비밀 값(`SESSION_SECRET`)이 설정에 있는지 검사하고 없으면 서버를 켜지 않는 기능: 혼자 쓰는 연습용 웹 서비스라 기본으로는 만들지 않습니다.
- 로그아웃할 때 브라우저에 남은 세션 쿠키를 지우는 기능: 혼자 쓰는 연습용 웹 서비스라 기본으로는 만들지 않습니다.
- 휴대폰처럼 좁은 화면에 맞추는 배치: 혼자 쓰는 연습용 웹 서비스라 기본으로는 만들지 않습니다.

끝 표시: `1회차-은색컵-` 뒤에 "웹 서비스의 기본 약속" 표의 포트 번호를 붙입니다. `PORT` 설정과 상관없이 표에 적힌 번호입니다.

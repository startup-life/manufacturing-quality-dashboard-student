# 1회차 보충 문서: 서버 뼈대와 로그인

이 문서는 AI 도구가 코드를 만들 때 읽는 자료입니다. 수강생은 이해하지 않아도 됩니다.

- 프롬프트가 요청한 일만 합니다. 이 문서의 내용을 한 번에 모두 만들지 않습니다.
- 앞 회차 문서와 다르면 번호가 큰 문서를 따릅니다. 이 회차가 바꾸는 앞 회차 약속은 없습니다(첫 문서입니다).
- 맨 끝의 끝 표시를 만들어 `AGENTS.md`가 말한 대로 답의 마지막 줄에 적습니다.

## 이번 회차가 끝나면 되는 것

`npm.cmd start`로 서버를 켜고 교육용 계정으로 로그인하고 로그아웃합니다. 로그인하면 각 주소에 빈 화면(품질 현황, 검사 등록, 검사 상세, 설정)이 하나씩 보이고, 없는 주소로 들어가면 안내가 나옵니다. 로그인하지 않으면 서버가 데이터를 주지 않습니다.

## 앱 뼈대

빈 앱 폴더에 처음 만드는 것입니다. 로그인, 머리 부분, 주소마다 다른 화면은 뒤 프롬프트에서 더하므로 여기서 만들지 않습니다.

- 프로그램: "추가 정보"의 프로젝트 설정 파일과 서버 코드 설정 파일을 앱 폴더 맨 위에 복사한 뒤 `npm.cmd install`로 받습니다. 함께 생기는 `package-lock.json`은 그대로 둡니다. 설치가 끝날 때 `vulnerabilities` 안내가 나와도 `npm audit fix`는 실행하지 않습니다.
- `.gitignore`: 앱 폴더 맨 위에 만들고 `node_modules`, `dist`, `.env`, `.clasp.json`, `runtime` 다섯 줄을 적습니다. 커밋할 때 비밀 값과 기록이 들어가지 않게 하는 파일입니다. `AGENTS.md`와 `docs` 폴더는 적지 않습니다.
- 서버: `npm.cmd start`로 켜지게 합니다("앱의 기본 약속"의 시작 명령). "앱의 기본 약속"의 포트와 켜질 때 안내를 따릅니다. 화면 파일은 "화면 주소"대로 보냅니다.
- 브라우저가 옛 화면을 기억하지 않게 서버의 모든 답에 `Cache-Control: no-store`를 붙입니다. 화면 파일을 고친 뒤 새로고침(F5)만 하면 고친 화면이 보이게 하려는 것입니다.
- 첫 화면: `public/index.html`에 큰 제목 "텀블러 공장 제조품질관리" 하나만 둡니다. 브라우저 탭 제목도 같은 글입니다. 어느 화면 주소로 들어와도 이 첫 화면이 나옵니다.
- 서버는 켜지 않습니다. `npm.cmd run build`로 오류가 없는지만 봅니다.

## 화면 서버 켜기

화면 서버를 켜거나 다시 켜는 일은 AI가 합니다. 사용자가 "화면 서버를 켜 주세요"나 "화면 서버를 다시 켜 주세요"라고 할 때 아래대로 합니다. 서버 코드(`src` 폴더)나 `.env`를 고친 답을 할 때도 서버가 켜져 있었거나 서버를 켤 때 나온 오류를 고쳐 달라는 요청이었으면 아래대로 합니다. 고친 답에서는 먼저 `npm.cmd run build`로 오류가 없는지 봅니다.

- 포트: "앱의 기본 약속"의 포트(4185)입니다. `.env`에 `PORT`가 있으면 그 값입니다.
- 켜져 있는지 보기: `Get-NetTCPConnection -LocalPort 4185 -State Listen -ErrorAction SilentlyContinue`를 실행합니다. 줄이 나오면 그 포트에서 요청을 받는 서버가 있는 것입니다.
- 켜기: "다시" 없이 "켜 주세요"라는 요청에서 이미 켜져 있으면 새로 켜지 않고 "이미 켜져 있습니다"라고 알립니다. 꺼져 있으면 AI가 명령을 실행하는 터미널이 아니라 새 PowerShell 창에서 켭니다. 아래 명령을 PowerShell로 실행합니다. 새 창이 열리고 그 창에서 서버가 켜집니다. 앞부분은 새 창이 이 PC의 프로그램 경로를 다시 읽게 하는 줄입니다. 사용자가 AI 도구를 연 뒤에 설치한 프로그램(5회차의 NotebookLM 도구 등)도 서버가 찾게 하려는 것이므로 빼지 않습니다.

```powershell
Start-Process powershell -ArgumentList '-NoExit','-Command','$env:Path = [Environment]::GetEnvironmentVariable(''Path'',''Machine'') + '';'' + [Environment]::GetEnvironmentVariable(''Path'',''User''); cd C:\ai-class\tumbler-factory; npm.cmd start'
```

- 다시 켜기: "다시 켜 주세요"라는 요청이면 이미 켜져 있어도 "이미 켜져 있습니다"로 끝내지 않고 다시 켭니다. 그 포트에서 요청을 받는 프로세스만 끕니다. `Get-NetTCPConnection -LocalPort 4185 -State Listen | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }`처럼 그 포트의 `OwningProcess`만 `Stop-Process`로 끄고, 프로그램 이름(`node` 등)으로 찾아 끄지 않습니다. 끄기 전에 그 프로세스가 이 앱의 서버인지 봅니다(아래 "이 앱의 서버인지 보기"). 포트가 비어 있는 것을 확인한 뒤 위 명령으로 새 창에서 켭니다. 꺼진 예전 창은 닫아도 된다고 사용자에게 알립니다.
- 이 앱의 서버인지 보기: `Get-CimInstance Win32_Process -Filter "ProcessId=(OwningProcess 번호)" | Select-Object Name, CommandLine`으로 이름과 명령 줄을 봅니다. 이름이 `node.exe`이고 명령 줄에 이 앱 `package.json`의 `start` 명령이 켜는 파일(예: `dist/main.js`)이 들어 있으면 이 앱 폴더에서 켠 서버입니다. 아니면 끄지 않고, 그 프로그램 이름을 사용자에게 알리고 멈춥니다. 다른 포트로 바꾸지 않습니다.
- 켠 뒤: `npm.cmd start`는 빌드부터 하므로 켜지는 데 수십 초가 걸립니다. "켜져 있는지 보기"를 몇 초마다 다시 하면서 1분쯤 기다립니다. 포트가 열리면 새 창(서버 창)에 `품질 대시보드 서버 실행 중: http://127.0.0.1:4185`가 나왔는지 보라고 사용자에게 알립니다. 1분이 지나도 열리지 않으면 서버 창의 빨간 글이나 `error TS`가 들어 있는 줄을 복사해 보내 달라고 합니다.
- `EADDRINUSE`: 다른 프로세스가 이미 그 포트를 쓰는 것입니다. 사용자가 이 글을 붙여 넣으면 그 포트의 프로세스가 이 앱의 서버인지 봅니다. 이 앱의 서버(이 앱 폴더에서 켠 npm 또는 node)면 "다시 켜기"대로 그 프로세스만 끄고 새 창에서 다시 켭니다. 아니면 끄지 않고, 무엇이 그 포트를 쓰는지 사용자에게 알리고 멈춥니다. 다른 포트로 바꾸지 않습니다.
- 설치나 빌드처럼 끝나는 명령은 새 창을 열지 않고 AI가 명령을 실행하는 터미널에서 합니다.

## 화면 주소

- 화면은 `public/index.html` 한 페이지입니다.
- `/api`로 시작하지 않는 주소는 `public` 폴더에 그 파일이 있으면 그 파일을, 없으면 `index.html`을 보냅니다. 어느 화면을 보여 줄지는 화면 쪽에서 주소를 보고 정합니다.
- 이 처리는 `src/main.ts`의 미들웨어로 둡니다. `public` 폴더의 파일 제공(`express.static`)을 먼저 두고, 그 뒤에 `/api`로 시작하는 요청은 다음 처리로 넘기고 나머지 주소에는 `sendFile`로 `index.html`을 보내는 미들웨어를 둡니다. NestJS 컨트롤러의 와일드카드 주소로는 만들지 않습니다.
- 화면 글은 모두 한국어입니다.

| 화면 주소 | 화면 이름 |
|---|---|
| `/` | 품질 현황(홈) |
| `/inspections/new` | 검사 등록 |
| `/inspections/(검사번호)` | 검사 상세 |
| `/settings` | 설정 |

- 로그인 전에는 주소와 상관없이 "로그인 화면"의 로그인 상자만 보입니다. 화면 내용, 머리 오른쪽, 노란 안내, 바닥글은 숨깁니다.
- 로그인한 뒤에는 주소에 맞는 화면 하나만 보입니다. 이 회차의 각 화면에는 위 표의 화면 이름만 제목으로 둡니다(홈은 "품질 현황"). 내용은 뒤 회차에서 채웁니다.
- 위 표에 맞는 화면이 없는 주소는 "페이지를 찾을 수 없습니다"와 "홈으로 가기" 버튼을 보여 줍니다. 버튼을 누르면 홈(`/`)으로 갑니다.
- 사이트 안 링크(머리 부분의 로고와 앱 이름, "설정", "홈으로 가기")를 누르면 페이지를 새로 불러오지 않고 주소와 화면만 바꿉니다(브라우저 방문 기록에 주소를 더함). 브라우저의 뒤로·앞으로 가기를 누르면 그 주소에 맞는 화면으로 바뀝니다.

## 서버 오류 문장

- 화면이 쓰는 데이터 주소는 `/api`로 시작합니다.
- 로그인 전 거절은 "로그인"을 따릅니다.
- 오류가 나면 `{"error": "한국어 문장"}` 모양으로 답하고 화면은 그 문장을 그대로 보여 줍니다.
- 오류 문장은 세 가지로 나눕니다. 모두 같은 `{"error": "한국어 문장"}` 모양입니다.

| 경우 | 문장 |
|---|---|
| 없는 `/api` 주소 | 로그인한 사람에게는 "요청한 주소를 찾을 수 없습니다."로 답합니다. 이 경우에만 이 문장을 씁니다. 서버 틀이 기본으로 내는 영어 답(`Cannot GET ...`)을 그대로 보내지 않습니다 |
| 코드가 일부러 낸 오류 | 그 문장을 바꾸지 않고 그대로 보냅니다. 예: "검사를 찾을 수 없습니다." |
| 예상하지 못한 오류 | 한국어 한 줄로 바꿉니다 |

## 로그인

- 로그인 상태는 `express-session`으로 서버 메모리에 저장합니다. 서버를 다시 켜면 로그인이 풀려도 됩니다.
- 로그인 데이터 주소는 아래 셋입니다. 이 셋을 제외한 `/api` 주소는 로그인한 사람에게만 답합니다. 로그인 전이면 없는 주소라도 `{"error": "로그인이 필요합니다."}`로 답합니다.

| 주소 | 하는 일 |
|---|---|
| `GET /api/session` | 로그인 상태를 답합니다. 로그인 전이면 `{"user": null}`, 로그인 뒤면 `{"user": {"username": 계정, "role": 역할 값}}`입니다 |
| `POST /api/login` | 로그인합니다. 요청은 `{"username": 계정, "password": 비밀번호}`이고 성공하면 `GET /api/session`과 같은 모양으로 답합니다. 계정이나 비밀번호가 틀리면 `{"error": "로그인 정보를 확인하세요."}`로 답합니다 |
| `POST /api/logout` | 로그아웃합니다. `{"user": null}`로 답합니다 |

- `POST /api/login`은 화면이 보낸 JSON 본문에서 계정과 비밀번호를 읽습니다. 로그인은 사용자가 브라우저에서 확인하므로 "앱의 기본 약속"의 서버 칸대로 컨트롤러로 만들어 본문이 읽히게 합니다.

교육용 계정입니다. 역할 값은 계정 이름과 같습니다. 화면에는 계정을 오른쪽 칸에 적힌 한국어로 표시합니다.

| 계정 | 비밀번호 | 화면 글 |
|---|---|---|
| `writer` | `writer1234!` | 작성자 |
| `reviewer` | `reviewer1234!` | 검토자 |
| `factory-user` | `factory1234!` | 품질관리 |

## 로그인 화면

- 로그인 상자 맨 위에 첫 화면의 큰 제목 "텀블러 공장 제조품질관리"를 두고, 그 아래에 계정 칸, 비밀번호 칸, "로그인" 버튼을 둡니다.
- 칸의 처음 값은 계정 `writer`, 비밀번호 `writer1234!`입니다. 비밀번호는 가려서 표시합니다.
- 페이지를 열면 `GET /api/session`으로 로그인 상태를 묻습니다. 이미 로그인했으면 로그인 상자를 바로 숨깁니다.
- "로그인" 버튼을 누르면 `POST /api/login`으로 로그인합니다. 성공하면 로그인 상자를 숨기고 지금 주소에 맞는 화면을 보여 줍니다. 실패하면 서버가 보낸 문장(예: "로그인 정보를 확인하세요.")을 로그인 상자 안에 빨간 글로 보여 주고 상자는 그대로 둡니다. 응답 본문에 `error`가 있는지 보고 실패 여부를 정합니다. 로그인 실패도 성공 상태 번호(2xx)로 올 수 있어 `response.ok`만으로는 구분할 수 없습니다.
- 머리 부분의 "로그아웃" 버튼을 누르면 `POST /api/logout`으로 로그아웃하고 로그인 상자를 다시 보여 줍니다. 이때 계정 칸과 비밀번호 칸을 처음 값으로 되돌리고, 빨간 글은 지웁니다. 머리 오른쪽, 노란 안내, 바닥글, 화면 내용은 숨깁니다.
- 로그인 전 첫 화면과 로그아웃 직후에는 새로고침하지 않아도 머리 오른쪽("설정", 사용자 표시, "로그아웃")이 보이지 않아야 합니다. 숨김을 `hidden` 속성으로 하면 CSS에서 지정한 `display`(예: `display: flex`)가 그 숨김을 덮지 않는지 확인합니다. 로그아웃할 때 사용자 표시 글자도 비웁니다.

## 화면 맨 위 줄

- 이 문서와 뒤 회차 문서는 이 줄을 "머리 부분"이라고 부릅니다.
- 화면 맨 위에 한 줄로 둡니다.
- 왼쪽: 로고 그림과 앱 이름 "텀블러 공장 제조품질관리". 둘 다 누르면 홈(`/`)으로 갑니다. 로그인 전에도 보여도 됩니다(로그인 전 화면에서 앱 이름이 머리 부분과 로그인 상자에 두 번 보여도 됩니다).
- 로고 그림: 텀블러 공장을 떠올리게 하는 단순한 그림 파일을 AI가 직접 그려 `public` 폴더에 둡니다(예: `public/logo.svg`). 글자 없이 도형 몇 개와 색 두세 가지로만 그립니다. 모양은 자유입니다.
- 오른쪽(로그인한 뒤에만 보임): "설정" 링크(`/settings`로 감), 사용자 표시, "로그아웃" 버튼.
- 이 줄을 만드는 요청에서는 오른쪽 세 가지("설정" 링크, 사용자 표시, "로그아웃" 버튼)를 모두 화면에 둡니다. 프롬프트에 "앱 이름과 내 계정"만 적혀 있어도 "설정" 링크와 "로그아웃" 버튼을 빼지 않습니다. 이 둘은 이 줄의 일부이고 뒤 번호 기능이 아닙니다.
- "로그아웃 동작은 다음 번호에서 만듭니다"는 버튼을 눌렀을 때의 동작("로그인 화면"의 로그아웃)만 뒤로 미룬다는 뜻입니다. 지금은 눌러도 아무 일도 하지 않는 "로그아웃" 버튼을 둡니다. "설정" 링크도 `/settings`로 가는 링크만 두고, 그 주소의 화면과 새로고침 없이 화면을 바꾸는 기능은 뒤 번호에서 만듭니다.
- 사용자 표시는 `계정 (화면 글)` 형식입니다. 예: "writer (작성자)", "reviewer (검토자)", "factory-user (품질관리)". 화면 글은 "로그인"의 계정 표를 따릅니다.

## 노란 안내와 바닥글

- 로그인한 뒤에만 보입니다. 로그인 전과 로그아웃한 뒤에는 숨깁니다.
- 노란 안내: 머리 부분 바로 아래에 노란 바탕의 안내 상자를 두고, "추가 정보"의 노란 안내 글을 글자 그대로 넣습니다.
- 바닥글: 화면 맨 아래에 "텀블러 공장 품질관리 시스템입니다."를 둡니다.

## 추가 정보

프롬프트에서 말하는 "이번 회차 추가 정보"는 아래 표의 파일입니다. 파일은 `docs/guide/files/`에 있고 프롬프트가 가리킬 때만 엽니다.

- `copy` 폴더: 파일을 그대로 앱 폴더에 넣습니다. 글자를 바꾸지 말고 복사합니다.
- `reference` 폴더: AI가 읽고 코드나 화면에 씁니다. 그대로 앱 폴더에 복사하지 않습니다.

| 프롬프트에서 부르는 이름 | 종류 | 파일 | 쓰는 법 |
|---|---|---|---|
| 프로젝트 설정 파일 | 복사 | `docs/guide/files/copy/package.json` | 앱 폴더 맨 위에 `package.json`으로 복사합니다. 패키지 버전은 이 파일로 고정합니다 |
| 서버 코드 설정 파일 | 복사 | `docs/guide/files/copy/tsconfig.json` | 앱 폴더 맨 위에 `tsconfig.json`으로 복사합니다 |
| 노란 안내 글 | 참고 | `docs/guide/files/reference/yellow-notice.md` | 파일에 적힌 한 줄을 글자 그대로 화면에 넣습니다 |

## 만들지 않는 것

- 요청마다 보안 확인 값(CSRF 토큰)을 주고받아 검사하는 기능: 혼자 쓰는 연습용 앱이라 만들지 않습니다.
- 보안 머리글을 더하는 기능(helmet 같은 패키지): 혼자 쓰는 연습용 앱이라 만들지 않습니다.
- 다른 사이트에서 온 요청(Origin 머리글)을 거절하는 검사: 혼자 쓰는 연습용 앱이라 만들지 않습니다.
- 세션 비밀 값(`SESSION_SECRET`)이 설정에 있는지 검사하고 없으면 서버를 켜지 않는 기능: 혼자 쓰는 연습용 앱이라 만들지 않습니다.
- 로그아웃할 때 브라우저에 남은 세션 쿠키를 지우는 기능: 혼자 쓰는 연습용 앱이라 만들지 않습니다.
- 휴대폰처럼 좁은 화면에 맞추는 배치: 혼자 쓰는 연습용 앱이라 만들지 않습니다.

끝 표시: `1회차-은색컵-` 뒤에 "앱의 기본 약속" 표의 포트 번호를 붙입니다. `PORT` 설정과 상관없이 표에 적힌 번호입니다.

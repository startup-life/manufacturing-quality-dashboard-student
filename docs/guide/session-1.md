# 1회차 보충 문서: 서버 뼈대와 로그인

이 문서는 AI 도구가 코드를 만들 때 읽는 자료입니다. 수강생은 이해하지 않아도 됩니다.

- 프롬프트가 요청한 일만 합니다. 이 문서의 내용을 한 번에 모두 만들지 않습니다.
- 앞 회차 문서와 다르면 번호가 큰 문서를 따릅니다. 이 회차가 바꾸는 앞 회차 약속은 없습니다(첫 문서입니다).
- 맨 끝의 끝 표시를 만들어 `AGENTS.md`가 말한 대로 답의 마지막 줄에 적습니다.

## 이번 회차가 끝나면 되는 것

`npm.cmd start`로 서버가 켜지고 교육용 계정으로 로그인과 로그아웃을 합니다. 로그인하면 주소마다 빈 화면(품질 현황, 검사 등록, 검사 상세, 설정)이 하나씩 보이고 없는 주소에는 안내가 나옵니다. 로그인하지 않으면 서버가 데이터를 주지 않습니다.

## 앱의 기본 약속

텀블러 공장 품질관리 웹앱입니다.

| 항목 | 약속 |
|---|---|
| 앱 이름 | 텀블러 공장 제조품질관리. 첫 화면의 큰 제목과 브라우저 탭 제목에 이 글을 씁니다 |
| 서버 | NestJS(TypeScript). 코드는 `src` 폴더에 둡니다. `/api` 데이터 주소는 NestJS 모듈에 등록한 컨트롤러로 만듭니다. 앱이 시작되기 전에 Express 객체(`getHttpAdapter().getInstance()`)에 주소를 직접 붙이면 그 주소는 NestJS가 요청 본문(JSON)을 읽기 전에 실행되어 본문이 비어 있습니다 |
| 화면 | HTML·CSS·JavaScript. 파일은 `public` 폴더에 둡니다. 로고 그림 파일도 여기에 둡니다 |
| 화면 모양 | 읽기 쉽고 단정하게 둡니다. 글자와 버튼은 큼직하게, 머리 부분은 한 줄로 둡니다 |
| 시작 명령 | `npm.cmd start`는 빌드한 뒤 `dist/main.js`로 서버를 켭니다 |
| 열리는 곳 | 이 PC 안(`127.0.0.1`)에서만 열립니다 |
| 포트 | 4185입니다. `PORT` 설정이 있으면 그 값을 씁니다 |
| 서버가 켜질 때 | 터미널에 `품질 대시보드 서버 실행 중: http://127.0.0.1:4185`를 보여 줍니다 |

## 앱 뼈대

빈 앱 폴더에 처음 만드는 것입니다. 로그인, 머리 부분, 주소마다 다른 화면은 뒤 프롬프트에서 더하므로 여기서 만들지 않습니다.

- 프로그램: "추가 정보"의 프로젝트 설정 파일과 서버 코드 설정 파일을 앱 폴더 맨 위에 복사한 뒤 `npm.cmd install`로 받습니다. 함께 생기는 `package-lock.json`은 그대로 둡니다. 설치 끝에 `vulnerabilities` 안내가 나와도 `npm audit fix`는 실행하지 않습니다.
- `.gitignore`: 앱 폴더 맨 위에 만들고 `node_modules`, `dist`, `.env`, `.clasp.json`, `runtime` 다섯 줄을 적습니다. 수강생이 회차 끝에 커밋할 때 비밀 값과 기록이 들어가지 않게 하는 파일입니다. `AGENTS.md`와 `docs` 폴더는 적지 않습니다.
- 서버: `npm.cmd start`로 켜지게 합니다("앱의 기본 약속"의 시작 명령). "앱의 기본 약속"의 포트와 켜질 때 안내를 따릅니다. 화면 파일은 "화면 주소"대로 보냅니다.
- 브라우저가 옛 화면을 기억하지 않게 서버의 모든 답에 `Cache-Control: no-store`를 붙입니다. 화면 파일을 고친 뒤 새로고침(F5)만 하면 고친 화면이 보이게 하려는 것입니다.
- 첫 화면: `public/index.html`에 큰 제목 "텀블러 공장 제조품질관리" 하나만 둡니다. 브라우저 탭 제목도 같은 글입니다. 어느 화면 주소로 들어와도 이 첫 화면이 나옵니다.
- 서버는 켜지 않습니다. `npm.cmd run build`로 오류가 없는지만 봅니다.

## 화면 주소

- 화면은 `public/index.html` 한 페이지입니다.
- `/api`로 시작하지 않는 주소는 `public` 폴더에 그 파일이 있으면 그 파일을, 없으면 `index.html`을 보냅니다. 어느 화면을 보여 줄지는 화면 쪽에서 주소를 보고 정합니다.
- 화면 글은 모두 한국어입니다.

| 화면 주소 | 화면 이름 |
|---|---|
| `/` | 품질 현황(홈) |
| `/inspections/new` | 검사 등록 |
| `/inspections/(검사번호)` | 검사 상세 |
| `/settings` | 설정 |

- 로그인 전에는 주소와 상관없이 "로그인 화면"의 로그인 상자만 보입니다. 화면 내용, 머리 오른쪽, 노란 안내, 바닥글은 숨깁니다.
- 로그인한 뒤에는 주소에 맞는 화면 하나만 보입니다. 이 회차의 각 화면에는 위 표의 화면 이름만 제목으로 둡니다(홈은 "품질 현황"). 내용은 뒤 회차에서 채웁니다.
- 위 표에 맞는 화면이 없는 주소는 "페이지를 찾을 수 없습니다"와 "홈으로 가기" 버튼을 보여 줍니다. 버튼을 누르면 홈(`/`)으로 갑니다.
- 사이트 안 링크(머리 부분의 로고와 앱 이름, "설정", "홈으로 가기")를 누르면 페이지를 새로 불러오지 않고 주소와 화면만 바꿉니다(브라우저 방문 기록에 주소를 더함). 브라우저의 뒤로·앞으로 가기를 누르면 그 주소에 맞는 화면으로 바뀝니다.

## 서버 오류 문장

- 화면이 쓰는 데이터 주소는 `/api`로 시작합니다.
- 로그인 전 거절은 "로그인"을 따릅니다.
- 오류가 나면 `{"error": "한국어 문장"}` 모양으로 답하고 화면은 그 문장을 그대로 보여 줍니다.
- 오류 문장은 세 가지로 나눕니다. 모두 같은 `{"error": "한국어 문장"}` 모양입니다.

| 경우 | 문장 |
|---|---|
| 없는 `/api` 주소 | 로그인한 사람에게는 "요청한 주소를 찾을 수 없습니다." 이 경우에만 이 문장을 씁니다. 서버 틀이 기본으로 내는 영어 답(`Cannot GET ...`)을 그대로 보내지 않습니다 |
| 코드가 일부러 낸 오류 | 그 문장을 바꾸지 않고 그대로 보냅니다. 예: "검사를 찾을 수 없습니다." |
| 예상하지 못한 오류 | 한국어 한 줄로 바꿉니다 |

## 로그인

- 로그인 상태는 `express-session`으로 서버 메모리에 저장합니다. 서버를 다시 켜면 로그인이 풀려도 됩니다.
- 로그인 데이터 주소는 아래 셋입니다. 이 셋을 제외한 `/api` 주소는 로그인한 사람에게만 답합니다. 로그인 전이면 없는 주소라도 `{"error": "로그인이 필요합니다."}`로 답합니다.

| 주소 | 하는 일 |
|---|---|
| `GET /api/session` | 로그인 상태를 답합니다. 로그인 전이면 `{"user": null}`, 로그인 뒤면 `{"user": {"username": 계정, "role": 역할 값}}`입니다 |
| `POST /api/login` | 로그인합니다. 요청은 `{"username": 계정, "password": 비밀번호}`이고 성공하면 `GET /api/session`과 같은 모양으로 답합니다. 계정이나 비밀번호가 틀리면 `{"error": "로그인 정보를 확인하세요."}`로 답합니다 |
| `POST /api/logout` | 로그아웃합니다. `{"user": null}`로 답합니다 |

- `POST /api/login`은 화면이 보낸 JSON 본문에서 계정과 비밀번호를 읽습니다. 서버를 켜서 확인할 수 없으므로 "앱의 기본 약속"의 서버 칸대로 컨트롤러로 만들어 본문이 읽히게 합니다.

교육용 계정입니다. 역할 값은 계정 이름과 같고 화면에는 오른쪽 칸에 적힌 한국어로 표시합니다.

| 계정 | 비밀번호 | 화면 글 |
|---|---|---|
| `writer` | `writer1234!` | 작성자 |
| `reviewer` | `reviewer1234!` | 검토자 |
| `factory-user` | `factory1234!` | 품질관리 |

## 로그인 화면

- 로그인 상자 맨 위에 첫 화면의 큰 제목 "텀블러 공장 제조품질관리"를 두고, 그 아래에 계정 칸, 비밀번호 칸, "로그인" 버튼을 둡니다.
- 칸의 처음 값은 계정 `writer`, 비밀번호 `writer1234!`입니다. 비밀번호는 가려서 보입니다.
- 페이지를 열면 `GET /api/session`으로 로그인 상태를 묻습니다. 이미 로그인했으면 로그인 상자를 바로 숨깁니다.
- "로그인" 버튼을 누르면 `POST /api/login`으로 로그인합니다. 성공하면 로그인 상자를 숨기고 지금 주소에 맞는 화면을 보여 줍니다. 실패하면 서버가 보낸 문장(예: "로그인 정보를 확인하세요.")을 로그인 상자 안에 빨간 글로 보여 주고 상자는 그대로 둡니다.
- 머리 부분의 "로그아웃" 버튼을 누르면 `POST /api/logout`으로 로그아웃하고 로그인 상자를 다시 보여 줍니다. 이때 계정 칸과 비밀번호 칸을 처음 값으로 되돌리고, 빨간 글은 지웁니다. 머리 오른쪽, 노란 안내, 바닥글, 화면 내용은 숨깁니다.
- 로그인 전 첫 화면과 로그아웃 직후에는 새로고침하지 않아도 머리 오른쪽("설정", 사용자 표시, "로그아웃")이 보이지 않아야 합니다. 숨김을 `hidden` 속성으로 하면 CSS의 `display` 지정(예: `display: flex`)이 그 숨김을 덮지 않는지 확인합니다. 로그아웃할 때 사용자 표시 글자도 비웁니다.

## 화면 맨 위 줄

- 이 문서와 뒤 회차 문서는 이 줄을 "머리 부분"이라고 부릅니다.
- 화면 맨 위에 한 줄로 둡니다.
- 왼쪽: 로고 그림과 앱 이름 "텀블러 공장 제조품질관리". 둘 다 누르면 홈(`/`)으로 갑니다. 로그인 전에도 보여도 됩니다(로그인 전 화면에서 앱 이름이 머리 부분과 로그인 상자에 두 번 보여도 됩니다).
- 로고 그림: 텀블러 공장을 떠올리게 하는 단순한 그림 파일을 AI가 직접 그려 `public` 폴더에 둡니다(예: `public/logo.svg`). 글자 없이 도형 몇 개와 색 두세 가지로만 그립니다. 모양은 자유입니다.
- 오른쪽(로그인한 뒤에만 보임): "설정" 링크(`/settings`로 감), 사용자 표시, "로그아웃" 버튼.
- 사용자 표시는 `계정 (화면 글)` 꼴입니다. 예: "writer (작성자)", "reviewer (검토자)", "factory-user (품질관리)". 화면 글은 "로그인"의 계정 표를 따릅니다.

## 노란 안내와 바닥글

- 로그인한 뒤에만 보입니다. 로그인 전과 로그아웃한 뒤에는 숨깁니다.
- 노란 안내: 머리 부분 바로 아래에 노란 바탕의 안내 상자를 두고, "추가 정보"의 노란 안내 글을 글자 그대로 넣습니다.
- 바닥글: 화면 맨 아래에 "텀블러 공장 품질관리 시스템입니다."를 둡니다.

## 추가 정보

프롬프트의 "이번 회차 추가 정보"는 아래 표의 파일입니다. 파일은 `docs/guide/files/`에 있고 프롬프트가 가리킬 때만 엽니다.

- `copy` 폴더: 파일을 그대로 앱 폴더에 넣습니다. 글자를 바꾸지 말고 복사합니다.
- `reference` 폴더: AI가 읽고 코드나 화면에 씁니다. 그대로 앱 폴더에 복사하지 않습니다.

| 프롬프트에서 부르는 이름 | 종류 | 파일 | 쓰는 법 |
|---|---|---|---|
| 프로젝트 설정 파일 | 복사 | `docs/guide/files/copy/package.json` | 앱 폴더 맨 위에 `package.json`으로 복사합니다. 패키지 버전은 이 파일로 고정합니다 |
| 서버 코드 설정 파일 | 복사 | `docs/guide/files/copy/tsconfig.json` | 앱 폴더 맨 위에 `tsconfig.json`으로 복사합니다 |
| 노란 안내 글 | 참고 | `docs/guide/files/reference/yellow-notice.md` | 파일에 적힌 한 줄을 글자 그대로 화면에 넣습니다 |

## 만들지 않는 것

- 요청마다 보안 확인 값(CSRF 토큰)을 주고받아 검사하는 기능: 혼자 쓰는 연습용 앱이라 만들지 않습니다.
- 보안 머리글을 더하는 기능(helmet 같은 패키지): 혼자 쓰는 연습용 앱이라 만들지 않습니다.
- 다른 사이트에서 온 요청(Origin 머리글)을 거절하는 검사: 혼자 쓰는 연습용 앱이라 만들지 않습니다.
- 세션 비밀 값(`SESSION_SECRET`)이 설정에 있는지 검사하고 없으면 서버를 켜지 않는 기능: 혼자 쓰는 연습용 앱이라 만들지 않습니다.
- 로그아웃할 때 브라우저에 남은 세션 쿠키를 지우는 기능: 혼자 쓰는 연습용 앱이라 만들지 않습니다.
- 휴대폰처럼 좁은 화면에 맞추는 배치: 혼자 쓰는 연습용 앱이라 만들지 않습니다.

끝 표시: `1회차-은색컵-` 뒤에 "앱의 기본 약속" 표의 포트 번호를 붙입니다. `PORT` 설정과 상관없이 표에 적힌 번호입니다.

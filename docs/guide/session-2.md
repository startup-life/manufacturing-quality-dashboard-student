# 2회차 보충 문서: 검사 등록과 품질 현황, 내 컴퓨터 저장

이 문서는 AI 도구가 코드를 만들 때 읽는 자료입니다. 수강생은 이해하지 않아도 됩니다.

- 프롬프트가 요청한 일만 합니다. 이 문서의 내용을 한 번에 모두 만들지 않습니다.
- 앞 회차 문서와 다르면 번호가 큰 문서를 따릅니다. 이 회차가 바꾸는 앞 회차 약속: `/api`로 시작하지 않는 주소의 처리(1회차 문서의 "화면 주소")에서 `/uploads`는 빼고 이 문서의 "저장"을 따릅니다.
- 맨 끝의 끝 표시를 만들어 `AGENTS.md`가 말한 대로 답의 마지막 줄에 적습니다.

## 이번 회차가 끝나면 되는 것

사진 여러 장을 붙여 검사를 등록하면 검사 상세 화면과 홈 품질 현황에 나옵니다. 기록은 이 컴퓨터의 `runtime` 폴더에 저장되어 서버를 껐다 켜도 남습니다.

## 저장

| 항목 | 약속 |
|---|---|
| 검사 기록 | 앱 폴더의 `runtime` 폴더 안 파일 하나(`runtime/local-state.json`)에 저장합니다. 서버를 껐다 켜도 남아야 합니다. 파일 안은 `{"inspections": [검사 한 건, ...]}` 모양입니다 |
| 등록한 사진 | `runtime/uploads` 폴더에 파일로 저장하고, 화면은 `/uploads/(파일 이름)` 주소로 봅니다. 파일 이름은 서버가 겹치지 않게 정합니다 |
| 폴더 만들기 | 서버가 켜질 때 `runtime` 폴더와 `runtime/uploads` 폴더가 없으면 만듭니다 |
| `/uploads` 주소 | `runtime/uploads` 폴더의 파일을 그대로 보냅니다. 1회차 문서 "화면 주소"의 `public` 파일과 `index.html`로 넘기지 않습니다 |
| Git | `runtime` 폴더는 `.gitignore`에 넣어 Git에 올리지 않습니다(이미 있으면 그대로 둡니다) |
| 서버가 켜질 때 | 서버 창에 `저장소: 내 컴퓨터(runtime/local-state.json)` 한 줄을 보여 줍니다 |
| 계정 | `writer`, `reviewer`, `factory-user` 세 계정 모두 검사를 등록하고 고칠 수 있습니다 |

## 제품과 검사기준

제품은 세 가지입니다.

| 제품 번호 | 제품 이름 | 색 | 화면 선택 글 |
|---|---|---|---|
| `P-SILVER` | 텀블러 실버 | 은색 | 은색 텀블러 |
| `P-WHITE` | 텀블러 화이트 | 흰색 | 흰색 텀블러 |
| `P-BLACK` | 텀블러 블랙 | 검정 | 검정 텀블러 |

검사기준은 앱 폴더 맨 위의 `standards` 폴더에 `Rev.A.json`, `Rev.B.json`으로 둡니다. 둘 다 제목 "교육용 텀블러 검사기준", 범위 "가상 훈련 기준; 실제 제조 규격이 아님"입니다.

파일 안은 아래 모양입니다. 값은 위 문장과 아래 표를 씁니다.

```text
{"revision": "Rev.A", "title": "제목", "scope": "범위", "weight_g": {"P-SILVER": {"min": 하한, "max": 상한}, "P-WHITE": {"min": 하한, "max": 상한}, "P-BLACK": {"min": 하한, "max": 상한}}}
```

중량 범위입니다. 단위는 g이고 양 끝을 포함합니다. Rev.A와 Rev.B는 은색 상한만 다릅니다.

| 기준 | `P-SILVER` | `P-WHITE` | `P-BLACK` |
|---|---|---|---|
| Rev.A | 345~355 | 445~455 | 545~555 |
| Rev.B | 345~354 | 445~455 | 545~555 |

화면은 제품 목록과 검사기준을 이 문서 "서버 기능 목록"의 `GET /api/products`와 `GET /api/standards/Rev.A`(또는 `Rev.B`)로 받습니다. 제품 목록은 서버 코드에 두어도 됩니다.

## 검사 한 건

서버와 화면이 주고받고 저장 파일에 들어가는 검사 한 건의 모양입니다.

```json
{"inspection_id": "INSP-20261029-3fa9c1d2", "product_id": "P-BLACK", "inspected_at": "2026-10-29 14:05:09", "revision": "Rev.A", "weight_g": 550, "memo": "", "decision": null, "content_version": 0, "images": ["/uploads/(파일 이름)"]}
```

| 항목 | 약속 |
|---|---|
| `inspection_id` | 검사번호입니다. 서버가 만듭니다. 모양은 `INSP-YYYYMMDD-xxxxxxxx`입니다(날짜는 등록한 날, x는 0~9·a~f 8글자). 예: `INSP-20261029-3fa9c1d2` |
| `product_id` | "제품과 검사기준"의 제품 번호입니다 |
| `inspected_at` | 한국 시각 "YYYY-MM-DD HH:MM:SS"(초까지) 글입니다. 화면의 날짜·시간 칸 값은 이 모양으로 바꿔 보내고, 초가 비어 있으면 00으로 채웁니다 |
| `revision` | `Rev.A` 또는 `Rev.B`입니다 |
| `weight_g` | 숫자이고 비우면 `null`이며 화면에는 "미측정"으로 보입니다 |
| `memo` | 글입니다. 비우면 빈 글입니다 |
| `decision` | 처음에 `null`이고 나중 회차에서 `OK`·`NG`·`HOLD`가 들어갑니다. 화면 글은 `OK` 정상, `NG` 불량, `HOLD` 보류, `null` 미판정입니다 |
| `content_version` | 0에서 시작하고, 상세 1번 탭에서 고쳐 저장할 때마다 1 오릅니다. 화면에는 "검사 기록 버전: N"으로 보입니다 |
| `images` | 사진 주소 목록입니다. 고른 순서대로 둡니다 |

## 사진 올리기

- 검사 등록 화면의 사진 칸은 사진 파일을 여러 장 한 번에 고르는 칸입니다(`<input type="file" accept="image/*" multiple>`). 사진 칸 아래에 고른 사진을 고른 순서대로 작게 미리 보여 줍니다. 다시 고르면 앞에 고른 사진 대신 새로 고른 사진으로 바꿉니다.
- 화면은 고른 사진을 `FileReader`로 읽어 data 주소(`data:image/...`)로 미리 보여 줍니다. 미리 보기와 등록에 같은 data 주소 글을 쓰도록 blob 주소는 쓰지 않습니다.
- 등록할 때 사진들을 그 data 주소 글로 다른 입력과 함께 한 번에 보냅니다. 사진 여러 장(8장 안팎)을 한 번에 보내도 등록되도록 서버가 받는 요청 크기 한도를 50mb로 올립니다. 이 PC에서만 쓰는 앱이라 모든 요청에 걸어도 됩니다.
- 이미 한도를 거는 코드가 있으면 그 값만 50mb로 바꿉니다. 없으면 NestJS의 `app.useBodyParser('json', { limit: '50mb' })`를 쓰고, `express.json()`을 `app.use`로 따로 더하지 않습니다.
- 사진 크기 줄이기나 형식 바꾸기는 하지 않아도 됩니다. 이를 위해 새 패키지를 더하지 않습니다.

## 화면

- 저장 버튼은 저장이 끝날 때까지 꺼 둡니다. 등록하는 버튼도 같습니다.
- 제품은 고르는 칸에서는 "제품과 검사기준"의 화면 선택 글(예: 은색 텀블러)로, 그 밖의 곳(상세 위쪽, 1번 탭, 홈 카드)에서는 제품 이름(예: 텀블러 실버)으로 보여 줍니다.
- 판정은 "검사 한 건"의 `decision` 화면 글로 보여 줍니다. 중량은 "552g"처럼 g을 붙이고, 없으면 "미측정"입니다.
- 화면끼리 오가는 링크와 버튼은 1회차의 새로고침 없이 화면 바꾸기를 그대로 씁니다.

## 검사 등록 화면

주소는 `/inspections/new`입니다(1회차 문서의 "화면 주소"). 홈 제목 옆의 "사진 등록" 버튼을 누르면 이 화면으로 갑니다.

| 칸 | 약속 |
|---|---|
| 제품 | 고르는 칸입니다. 고르는 글은 화면 선택 글(은색 텀블러, 흰색 텀블러, 검정 텀블러)이고 보내는 값은 제품 번호입니다. 처음에는 목록 첫 제품(은색 텀블러)이 골라져 있습니다 |
| 검사일시 | 날짜와 시간을 초까지 고르는 칸입니다(`<input type="datetime-local" step="1">`). 처음 값은 화면을 연 때의 한국 시각입니다 |
| 검사기준 | Rev.A와 Rev.B 가운데 고르는 칸입니다. 처음에는 Rev.A입니다 |
| 중량(g) | 숫자 칸입니다. 비워 둘 수 있고, 비우면 `null`로 보냅니다 |
| 메모 | 여러 줄 글 칸입니다. 비워 둘 수 있습니다 |
| 중량 범위 줄 | 고른 제품과 검사기준의 범위를 "기준 중량: 545~555g" 꼴 한 줄로 보여 줍니다. 제품이나 검사기준을 바꿀 때마다 바뀝니다. 범위는 `GET /api/standards/(기준 이름)`의 `weight_g`에서 읽습니다 |
| 사진 칸 | 이 문서 "사진 올리기"를 따릅니다 |
| "검사 등록" 버튼 | 화면 맨 아래에 둡니다. 누르면 입력과 사진을 `POST /api/inspections`로 한 번에 보냅니다. 고른 사진이 없으면 보내지 않고 "사진을 골라 주세요."를 보여 줍니다. 저장되면 받은 검사번호의 상세 화면(`/inspections/(검사번호)`)으로 넘어갑니다. 실패하면 서버가 보낸 문장을 버튼 근처에 보여 주고 입력한 값은 그대로 둡니다 |

## 검사 상세 화면

주소는 `/inspections/(검사번호)`입니다. 화면을 열 때 `GET /api/inspections/(검사번호)`로 검사 한 건을 받습니다. 오류가 오면 그 문장(예: "검사를 찾을 수 없습니다.")만 보여 줍니다.

| 자리 | 약속 |
|---|---|
| 위쪽 | 검사번호, 제품 이름, 판정 글, "검사 기록 버전: N"을 보여 줍니다. 판정이 없으면 "미판정"입니다 |
| 탭 | 위쪽 아래에 탭 네 개 "① 사진·측정값", "② AI 결과 확인", "③ 검사기준과 비교하기", "④ 내 판단 기록"을 둡니다. 처음엔 1번 탭이 보이고, 고른 탭에는 표시를 합니다. 2~4번 탭에는 "이 탭은 나중 회차에서 만듭니다."만 적습니다. 이 안내 글은 탭을 만들 때 함께 넣습니다. 다음 번호에서 만드는 것은 1번 탭 안의 내용뿐입니다 |
| 1번 탭 왼쪽 | 첫 사진을 크게, 그 아래에 모든 사진을 `images` 순서대로 작게 보여 줍니다. 작은 사진을 누르면 큰 사진이 그 사진으로 바뀌고, 지금 크게 보이는 작은 사진에 표시를 합니다 |
| 1번 탭 오른쪽 | 제품 이름, 검사일시, 기준(`revision`), 중량, 메모를 보여 줍니다. 메모가 비어 있으면 "없음"입니다 |
| 1번 탭 고치기 | 오른쪽 정보 아래에 제품(등록 화면과 같은 고르는 칸), 검사일시(등록 화면과 같은 날짜·시간 칸), 중량 칸과 "저장" 버튼을 둡니다. 칸에는 지금 값을 넣어 둡니다. "저장"을 누르면 세 값을 `PATCH /api/inspections/(검사번호)`로 보내고, 성공하면 검사를 다시 받아 화면을 새로 그립니다. 실패하면 서버가 보낸 문장을 보여 줍니다. 기준과 메모는 1번 탭에서 고치지 않습니다 |

## 홈 화면

주소는 `/`입니다. 로그인하면 현황을 불러오고, 로그아웃하면 숫자와 카드를 지웁니다. 다른 화면에서 홈으로 돌아와도 다시 불러옵니다.

| 자리 | 약속 |
|---|---|
| "사진 등록" 버튼 | 홈 제목 옆에 둡니다. 누르면 검사 등록 화면으로 갑니다 |
| 날짜 칸 | 날짜를 고르는 칸입니다(`<input type="date">`). 처음에는 날짜 없이 `GET /api/home`을 불러 받은 `date`(가장 최근 검사일)를 넣습니다. 기록이 없으면 비워 둡니다. 날짜를 바꾸면 그 날짜로 숫자와 검사 카드를 다시 불러옵니다 |
| 숫자 카드 4개 | 날짜 칸 아래에 "검사 건수"(`total`), "NG 건수"(`ng`), "HOLD 건수"(`hold`), "보고서 검토 대기"(`review_pending`)를 둡니다. 값은 `GET /api/home?date=(날짜)`에서 읽습니다 |
| 검사 카드 | 숫자 카드 아래에 그 날짜의 검사를 `GET /api/inspections?date=(날짜)`로 받아 카드로 보여 줍니다. 카드에는 첫 사진, 검사번호, 제품 이름, 중량, 판정 글을 둡니다. 카드를 누르면 그 검사의 상세 화면으로 갑니다. 그 날짜에 검사가 없으면 "이 날짜에 등록한 검사가 없습니다."를 보여 줍니다 |
| 숫자 눌러 거르기 | 처음에는 아무 숫자 카드도 켜지 않습니다. "NG 건수"를 누르면 `decision=NG`, "HOLD 건수"는 `decision=HOLD`, "보고서 검토 대기"는 `review=pending`을 붙여 검사 카드를 다시 받습니다. 누른 숫자 카드에만 켜진 표시(굵은 테두리나 진한 색처럼 눈에 띄게, 마우스를 올렸을 때의 색과 다르게)를 합니다. 켜진 카드를 다시 누르면 거르기를 끄고 모두 보여 줍니다. "검사 건수"를 누르면 거르기를 끄고 모두 보여 줍니다. 걸러서 하나도 없으면 "이 날짜에 이 종류의 검사가 없습니다."를 보여 줍니다. 날짜를 바꿔도 켜 둔 거르기는 그대로 둡니다 |

## 설정 화면

2-14 단계를 수행할 때는 [단계 보충](steps/session-2/2-14.md)도 함께 읽습니다. 다른 번호의 기능은 앞당기지 않습니다.

주소는 `/settings`입니다. "저장소 상태" 칸을 두고, 화면을 열 때마다 `GET /api/operations`를 불러 `"저장소: " + label`을 보여 줍니다. 2회차에는 "저장소: 내 컴퓨터"입니다. 이 주소가 서버에 아직 없으면 함께 만듭니다("서버 기능 목록"의 `GET /api/operations`).

## 서버 기능 목록

"검사 한 건"은 이 문서 "검사 한 건"의 모양입니다. 오류는 1회차 문서 "서버 오류 문장"의 모양으로 답합니다.

| 주소 | 하는 일과 요청 | 답 |
|---|---|---|
| `GET /api/products` | 제품 목록 | `[{"product_id": 제품 번호, "name": 제품 이름, "color": 색, "label": 화면 선택 글}, ...]` |
| `GET /api/standards/Rev.A` (또는 `Rev.B`) | 검사기준 | "제품과 검사기준"의 파일 내용. 다른 기준 이름이면 "검사기준을 찾을 수 없습니다." |
| `POST /api/inspections` | 검사 등록(사진 포함). 요청은 `{"product_id", "inspected_at", "revision", "weight_g", "memo", "images": [data 주소 글, ...]}`입니다. 사진을 `runtime/uploads`에 파일로 저장하고 검사 한 건을 저장 파일에 더합니다. `images`가 비어 있으면 "사진을 골라 주세요." | 저장한 검사 한 건. `images`는 `/uploads` 주소 목록입니다 |
| `GET /api/inspections/(검사번호)` | 검사 한 건 | 검사 한 건. 없으면 "검사를 찾을 수 없습니다." |

## 만들지 않는 것

- 사진을 나눠 고르면 앞 사진에 이어 더하기, 고른 사진마다 붙는 "빼기" 버튼: 혼자 쓰는 연습용 앱이라 만들지 않습니다.
- 요청이 너무 클 때 따로 내는 "사진이 너무 큽니다" 안내 문장: 학습 사진은 작아서 50mb 한도에 닿지 않으므로 만들지 않습니다.
- 등록한 사진 주소(`/uploads`)를 로그인한 사람만 보게 막기: 혼자 쓰는 연습용 앱이라 만들지 않습니다.

끝 표시: `2회차-저울눈금-` 뒤에 "제품과 검사기준"의 Rev.B P-SILVER 중량 상한을 붙입니다.
